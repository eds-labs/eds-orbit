# Orbit API v1

Same-origin `/api` proxy. Session via Better Auth. Every modifying request requires Origin matching APP_ORIGIN; all project resources require membership. Owner can administer, editor creates/reviews content, viewer reads. No public signup. Setup needs installation token (`setupToken` input), owner email/name/password/workspaceName. Token is created only in local ignored runtime configuration.

- GET /api/setup `{configured:boolean}`; POST /api/setup `{name,email,password,workspaceName,setupToken}` -> `{configured:true}` then sign in.
- POST /api/auth/sign-in/email `{email,password}`; POST /api/auth/sign-out; GET /api/me -> `{user:{id,name,email},workspaces:[],projects:[]}`.
- GET /api/projects -> `{items: Project[]}`; POST `{name,timezone,language}` -> Project. Project fields id,workspaceId,name,timezone,language,mode,paused,generation.
- GET /api/projects/:projectId/modules any member -> `{switchable:boolean,modules:[{id,displayName:{en,de},version,dependsOn,enabled,explicit,changedBy,changedAt}]}` in dependency order (WP1.4, ADR 0009). `explicit:false` means the registry default applies. PUT /api/projects/:projectId/modules/:moduleId owner `{enabled:boolean}` -> the same body; answers 404 `NOT_FOUND` while `ORBIT_MODULES` is off, `MODULE_NOT_FOUND` (404) for an unknown module, `MODULE_DEPENDENCY_DISABLED` (409) when enabling a module whose dependency is off, `MODULE_REQUIRED` (409) when disabling a module an enabled module depends on. Every change writes the audit event `module.enabled` or `module.disabled`; nothing is deleted. While `ORBIT_MODULES` is on, activation is enforced (WP2.4, `docs/MODULE_ACTIVATION.md`): every route under `/api/projects/:projectId/` that a disabled module contributes, its actions (`POST …/actions/:name`) and its collections (`GET/POST …/:collection`) answer `MODULE_DISABLED` (404) after the membership check. With the flag off every module keeps working. New projects get the registry defaults recorded on creation.
- GET /api/projects/:projectId/dashboard -> `{project,counts,exceptions,publications,jobs,budget,readiness}`.
- GET /api/projects/:projectId/attention (any member; UI restructure §4.1) -> `{items, counts, status}`: what needs the member's attention. `items` are `{id, moduleId, kind, severity: "critical"|"warning"|"info", count?, dueAt?, since?, params, navKey, link}`, collected from every module that is enabled for the project and not hidden from the member (module role `none`), each read with the member's role in that module, plus the platform's own items; sorted by severity, then `dueAt` ascending (undated last), then `since` ascending, then `id`; at most 50. `counts` maps each `navKey` to the sum of `count ?? 1` over its items before the cap (an aggregated item adds its `count`). `status` is `{paused, mode?, aiMonth?: {spentMicros, limitMicros?}}`: `mode` is the project's mode (the `project.mode` of GET /dashboard that the marketing overview's mode band shows, set when a policy is activated; ruling R25), present only while marketing is enabled and visible to the member; `aiMonth` is present only for owners and editors (`platform.project.write`, the level of GET /ai-cost; ruling R26): `spentMicros` is the project's AI spend since the start of the UTC calendar month as the budget enforcement counts it (settled amounts plus reserved, in-flight and unclear reservations, released ones excluded), `limitMicros` the active policy's monthly limit, `null` when no active policy sets one, and absent when the policies are hidden from the member (module role `none`: unknown, not "no limit"). The platform's items are `platform_worker_down` (critical, no worker heartbeat within 30 s, any member), `platform_cost_unknown` (warning, owners, `params.micros` = unclear reservations this UTC month) and `platform_action_request` (warning, owners, aggregated open owner decisions, navKey `approvals`). Every object counts once in `counts`: a `marketing_exception` item stands for one open exception code (no `count`; `params.affected` = the resources it names, ruling R19); support lists at most five breached and five at-risk tickets and the rest of each kind as one item `support:sla:breached:more` / `support:sla:at_risk:more` (`count`, the earliest remaining `dueAt`, `params: {}`), and `support_unassigned` counts only unassigned tickets without an SLA item of their own (`params.othersListed: true` when some have one; no item when none are left; R20). `marketing_run_problem` (`RUN_FAILED`, `BUDGET_EXHAUSTED`) follows the agent activity's health rules (R21). The web renders the text from `kind` and `params`; `link` is an in-app path below `/p/:id`. Read-only, no audit row, `Cache-Control: no-store`. A module contribution that fails makes the whole read answer 500 `REQUEST_FAILED` (logged with the module id) rather than leaving its items out. The web shell reads it as `/attention?revision=<workspace revision>` (the server ignores the query; it only separates revisions) and reuses a response per project and revision for 30 s across navigations (ruling R15); a `navKey` is the route key of a sidebar entry, so `counts` are the badges, and a `navKey` without a visible entry (such as `approvals` while marketing is off) shows no badge. A kind the web does not know renders as a generic row (module name, kind, "Open"), so new kinds are additive.
- GET /api/projects/:projectId/:collection -> `{items: Entity[]}`. Entity `{id,kind,version,data,createdAt,updatedAt}`. Collection names in packages/schemas/src/index.ts.
- POST /api/projects/:projectId/sources with schema `source`; POST facts uses knowledge contract; POST missions with schema `mission`; POST content schema `content`; POST policies schema `policy`; POST metrics/preference/experiments corresponding schemas.
- PATCH /api/projects/:projectId/content/:id `{version,data:ContentInput}`; edits invalidate review and publication intents. Other generic writes forbidden.
- POST /api/projects/:projectId/actions/import `{sourceId,externalId,title,text,mimeType,language}` or `{sourceId,url}`. Inline text max 1 MB. Returns imported document.
- POST .../actions/retrieve `{query,language,purpose:'public'|'internal',at?}` -> EvidencePack entity or object.
- POST .../actions/revoke-source `{sourceId}` owner only; immediate tombstone and downstream invalidation.
- POST .../actions/run-mission `{missionId}` -> durable job. Local test drafts explicitly synthetic; live generation requires paid-test/automation budget.
- POST .../actions/review `{contentId,version}` -> server claim/evidence check.
- POST .../actions/approve `{contentId,version,packageHash}` owner only; obtain hash via POST .../actions/preflight `{contentId}`. No stale approvals.
- POST .../actions/publish `{contentId,version,scheduledAt?}` -> durable local intent; test executor never contacts external providers.
- POST .../actions/pause `{paused:boolean}` owner only; invalidates pending writes and exposes remote cancellation risk.
- POST .../actions/analyze `{campaign?:string}` -> deterministic aggregate-backed insight and bounded follow-up.
- POST .../actions/retry `{jobId}` editor/owner; bounded recovery only.
- POST .../actions/add-member `{email,name,password,role:'owner'|'editor'|'viewer'}` owner -> `{added:true}`. Creates the account when the address is unknown (name/password are ignored for an existing account) and adds it to the workspace as viewer and to the project with `role`. A project owner who does not own the workspace may add only new accounts or existing workspace members, only as editor/viewer, and may not change an existing owner's role; otherwise `WORKSPACE_OWNER_REQUIRED` (403) before anything is created. Every addition writes the project audit event `project_member.add` (resource: user ID; metadata `{role,previousRole,createdUser}`, no e-mail address). No member removal endpoint yet.
- GET .../export -> project export omitting secrets; GET .../content/:id/export -> article/markdown.
- GET .../knowledge-health -> conflicts,expiredFacts,failedImports,staleSources,missingEvidence,impacts (real data).
- POST .../actions/connector `{provider:'postiz'|'matomo'|'slack',baseUrl?,credential,siteId?,channelId?}` owner; encrypted server-side. GET connectors never returns credential. POST .../actions/connector-health `{connectorId}` owner triggers read-only capability check.

- GET /api/projects/:projectId/agent-runs?cursor&kind editor/owner -> `{runs:[{id,kind,agentName,taskClass,subjectType,subjectId,missionId,status,errorCode,startedAt,durationMs,modelCalls,toolCalls,inputTokens,cachedTokens,cacheWriteTokens,outputTokens,reasoningTokens,costMicros}],nextCursor}`. Newest first, 50 per page; `cursor` is the last run ID of the previous page (`INVALID_CURSOR` if unknown in the project); `kind` is `chat|generation|retrieval|ingestion|reindex|evaluation|image`. Token sums and `costMicros` (string) aggregate the run's spans; no prompts, outputs or provider text are returned.
- GET /api/projects/:projectId/ai-cost?from&to&groupBy editor/owner -> `{from,to,groupBy,rows:[{key,reservedMicros,settledMicros,unknownMicros,count}]}`. `from`/`to` are ISO datetimes (default: start of current UTC month to now); `groupBy` is `day` (UTC date, default), `category`, `model`, `taskClass` or `mission`. Amounts are USD micros as strings; released reservations are excluded; `key` is `null` for unattributed rows. Errors: `INVALID_RANGE` (to not after from), `RANGE_TOO_LARGE` (over 93 days).
- POST /api/projects/:projectId/chat/packages/:id/attach-image editor/owner (the package's requester) `{deliverableKeys:string[1..4]}` -> package snapshot. Attaches the package's generated image to the chosen drafts after an owner approved its usage rights; each draft is reviewed again and approvals or publications of its previous version are blocked. Errors `ASSET_RIGHTS_REQUIRED`, `DRAFT_REUSED` (the draft was reused from another package; revise it first), `IMAGE_NOT_GENERATED`, `PACKAGE_IMAGE_REQUIRED`, `CAPTION_TOO_LONG`, `ALREADY_SCHEDULED`, `DRAFT_SUPERSEDED`, `REVISION_IN_PROGRESS`, `CONTENT_PACKAGES_DISABLED`; none of the chosen drafts change on an error. Package snapshots report `image.rightsApproved`, `image.assetVersion` and `content.assetId`.
- POST /api/projects/:projectId/chat/packages/:id/unschedule editor/owner (the package's requester or an owner; not gated by `ORBIT_CONTENT_PACKAGES`) `{deliverableKey}` -> `{result,publicationStatus,package}` with `result` `canceled|withdrawn|handoff_in_progress|not_retractable|nothing_scheduled`. Withdraws open schedule proposals and takes the publication back before the handoff; a handed-over post is reported, never retracted. Package snapshots report a pending move as `schedule.move:{status,scheduledAt,actionRequestId}`.
- GET /api/projects/:projectId/action-requests owner -> `{items:[{id,version,actionType,riskClass,packageHash,costCeilingMicros,expiresAt,createdAt,requestedBy,summary:{prompt,model,maxCostMicros,size,quality,channel,scheduledAt,body,executionMode,assetId,packageGoal}}]}`. Pending, unexpired requests whose action type needs an owner decision (`image.generate`, `content.schedule`), newest first, at most 50. A `content.schedule` item shows the exact post text, channel, slot and execution mode.
- POST /api/projects/:projectId/action-requests/:id/decide editor/owner `{version,packageHash,decision:"approve"|"reject"}` -> `{id,version,status}`. Decides one exact action request (ADR 0008 addendum). The action type sets the deciding role (`image.generate` and `content.schedule`: owner; `content_package.start`: the requesting editor or owner) and rechecks its payload; errors `ACTION_REQUEST_STALE`, `ACTION_REQUEST_EXPIRED`, `ACTION_REQUEST_NOT_PENDING`, `OWNER_REQUIRED`, `PACKAGE_STALE`, `SCHEDULE_STALE`, `SCHEDULE_SLOT_TAKEN`, `CONTENT_PACKAGES_DISABLED`, or a preflight blocker of the scheduled post (the decision is then not recorded). A repeated identical decision returns the recorded result. Conversation detail (`GET …/chat/conversations/:id`) additionally returns `packages` for the requesting user: `{id,version,goal,status,ceilingMicros,image,actionRequest,deliverables:[{key,channelId,channelName,platform,plannedSlotAt,status,errorCode,content,review,schedule}]}`; `schedule` is null or `{status,scheduledAt,contentId,actionRequestId,executionMode,publicationId,blockers}` with status `awaiting_approval|stale|expired|rejected|canceled` before the decision and `scheduled` or the publication status after it; `image` is `{prompt,maxCostMicros,status,assetId,href,errorCode}` with status `planned|awaiting_approval|queued|running|generated|outcome_unknown|failed|canceled`.
- POST /api/projects/:projectId/chat/packages/:id/cancel editor/owner, requester only -> package snapshot with status `canceled`. Withdraws the start or image decision, cancels queued jobs and archives missions without a draft; drafts, running jobs and already sent requests are reported as they are. `NOT_FOUND` for another user's package.

Errors `{error:{code,message}}`, no stack, provider text, source snippets or SQL. Specific shapes are validated server-side and generated OpenAPI supplements this contract.

`GET /api/projects/:projectId/indexes` returns owner-visible generation/evaluation state. Read collections include `calendar_blocks`, `community_questions`, `community_groups`, `work_packages`, `followup_plans`, `connector_verifications` and `index_evaluations`. Index evaluation query inputs are private project data, not public content.

`POST /api/workspaces/:workspaceId/pause {paused}` requires a current workspace owner and atomically fences all current projects before per-project reconciliation. Resuming does not restore invalidated approvals or intents. New projects start in Observe.

`POST /api/slack/:workspaceId/:projectId/interactions` is one of two write routes exempted from browser Origin checking: it requires the exact raw signed body, current timestamp, replay protection, team/channel and current mapped-owner authorization. It returns no sensitive details.

Orbit Telegram bot (Orbit Agents, `ORBIT_AGENTS=true`; every route answers 404 while it is off): `GET /api/projects/:projectId/telegram` → `{status, linkedAt}`, `POST .../telegram/connect {token}` → `{linkCode, expiresAt}` (10 min, single use) and `POST .../telegram/disconnect` are owner-only. The bot token is stored encrypted and never returned; `telegram_connections` is not a readable collection and is excluded from the project export. `POST /api/telegram/:projectId/:connectionId` is the second Origin-exempt write route: Telegram's webhook, authenticated by the per-connection `X-Telegram-Bot-Api-Secret-Token` (only its hash is stored; a wrong one gets 401 and an audit event) and the bound private chat. An unknown project, an unknown connection or another project's connection gets the same 401. The bot counts as connected only while the user it is bound to is still a project owner. It handles `/start <code>`, Stop (`stop:` callback, withdraws an assignment post before handoff) and `/pause` with an inline confirmation; resuming is only possible in Orbit.

Orbit Agents assignments (`ORBIT_AGENTS=true`; every route answers 404 while it is off, before authentication):

- `GET /api/projects/:projectId/assignments` (any member) → `{timezone, paused, items}`. Each item has `id, version, name, status, kind, contentType, channels, channelNames, schedule, image, vetoMinutes`, `nextRunAt` (when the next run starts preparing; null when none is due, the assignment is not active or the project is paused), `monthCostMicros` (this UTC month, counted like the budget check: settled reservations at their cost, open ones at their reserved amount) against `monthlyBudgetMicros`, and `actionRequestId` (the open `assignment.confirm` request of a draft, else null). Ended assignments come last. The route replaces the generic `assignments` collection read. The Orbit Core tool `assignment_list` reports the same `monthCostMicros`. `assignment_runs` and `agent_tasks` are not readable collections (the generic read answers 400); runs reach people through `run_status` and the AI runs page.
- `POST /api/projects/:projectId/assignments/:id/status {status: "paused"|"active"|"ended", version}` → `{id, version, status}`. Editors pause and end; only an owner resumes (`OWNER_REQUIRED`); viewers get 403. A version other than the current one is `VERSION_CONFLICT`. Content and time changes go through the Orbit chat and a new confirmation.
- `GET /api/projects/:projectId/assignment-posts` (any member) → `{items}`: assignment posts Orbit still holds (`intent_created`, or `blocked_dependency` before any handoff), earliest slot first, with `id, version, status, reason, channel, channelName, scheduledAt, vetoDeadline, excerpt` (280 characters), `assignmentId, assignmentName`. This is the approvals-page fallback to the Telegram preview.
- `POST /api/projects/:projectId/publications/:id/veto {version, reason?}` (editor or owner) → `{result: "vetoed"|"already_handed_over"|"not_found"}`: the same Stop as the bot's button (source `orbit`). A post Postiz already has answers `already_handed_over` and stays unchanged; a reason is kept as a proposed preference. Posts the owner released (below) can be stopped the same way.
- `GET /api/projects/:projectId/assignment-drafts` (any member) → `{items}`: assignment drafts that wait for the owner's release (social drafts left `needs_review` by the review, without a linked bot or while agent review authority is off), of runs that are not canceled, whose assignment's confirmation still covers them and whose run slot is today or later, earliest first, with `id, version, channel, channelName, slotAt, excerpt` (280 characters), `assignmentId, assignmentName`, `agentApproved` (the review agent approved the text) and `problems` (codes the review left open).
- `POST /api/projects/:projectId/assignment-drafts/:id/release {version}` (owner only; editors and viewers get 403) → `{result: "released"|"already_released", publicationId, scheduledAt, requestedAt}`. Records the owner's content review, lets the draft's mission publish exactly this post, records the package approval in assisted mode and schedules it through the publisher without a veto window at its run slot (`requestedAt`), or at the next free half hour that day when the slot is taken or has passed (`scheduledAt`). Refusals (409, nothing changes): `SLOT_UNAVAILABLE`, `VERSION_CONFLICT`, `DRAFT_NOT_AWAITING_OWNER`, `DRAFT_NOT_PUBLISHABLE` (blog or newsletter), `ASSIGNMENT_NOT_CONFIRMED`, `RUN_CANCELED`, `POLICY_REQUIRED`, or the preflight blockers joined by commas. Not an assignment draft: 404. A second release answers `already_released` with the same publication.
- `GET …/assignment-posts` items also carry `ownerReleased`; `vetoDeadline` is null for a post the owner released.
- Delivery as Postiz drafts (R73): assignment content has `delivery: "publish"|"postiz_draft"` (absent = `publish`; confirmed and hashed like the other fields; `postiz_draft` only for `social`, and refused with `POSTIZ_DRAFTS_DISABLED` (409) while `ENABLE_POSTIZ_DRAFTS` is off). `GET …/assignments` items, the `assignment.confirm` inbox summary and the chat card carry `delivery`. `GET …/assignment-posts` items carry `delivery`; items with `delivery: "postiz_draft"` are the assignment's Postiz draft handoffs whose slot is ahead (`id`, `version`, `status` = `queued`|`sending`|`accepted`|`outcome_unknown` of the handoff, `scheduledAt` = its slot, `vetoDeadline` null) and cannot be stopped (the veto route answers `not_found` for them). `GET …/assignment-drafts` items carry `delivery`. The release answers `{result, delivery, publicationId, postizDraftId, scheduledAt, requestedAt}`: with `postiz_draft` it books a Postiz draft at the slot (`publicationId` null) instead of scheduling a publication, grants no publish right and is refused with `POSTIZ_DRAFTS_DISABLED` while drafts are off. An unclear draft handoff is resolved with the existing `postiz-draft-resolve` action; for an assignment draft "not_created" gives its slot back. The confirmation records `delivery`. `postiz-draft-handoff` answers `POSTIZ_DRAFT_QUEUED` (409) while an assignment delivery of the content is queued. `run_status` deliverables add the outcome `postiz_draft_failed`.
- `GET /api/projects/:projectId/agent-activity` (any member; 404 while Orbit Agents is off) → `{timezone, paused, activeAssignments, health, runs, next}` for the overview. `runs` are the open assignment runs (`planned`, `running`), else the most recent run, at most three, each with `id, assignmentId, assignmentName, date, status, plannedAt, updatedAt, firstSlotAt, costMicros, ceilingMicros, delivery` and `steps` (`key, role, status, dependsOn, optionalDependsOn, errorCode, channel, channelName`); an open run's step status follows its agent task (`outcome_unknown` counts as `failed`). `next` lists up to six items earliest first: `run_start` (an active assignment's next run), `post` and `postiz_draft` (`assignment-posts`) and `owner_release` (`assignment-drafts`), each `{kind, at, assignmentName, channelName, status}`. `health` is `{state: "ok"|"attention"|"problem"|"paused", issues}` with issues `{code, severity, count}`: `PROJECT_PAUSED`, `RUN_FAILED` (problem; failed runs updated in the last 24 hours), `RUN_PARTIAL`, `DRAFTS_AWAIT_RELEASE`, `POSTS_BLOCKED`, `DRAFT_HANDOFF_UNCLEAR` and `BUDGET_EXHAUSTED` (an active assignment spent its monthly budget). Read only; no text excerpts.
- Shared text and format (R76, R77): assignment content has `sharedAcrossChannels: boolean` (absent = `false`) and an optional `format: {minChars, maxChars, hashtags: {min, max}, paragraphs, cta?}`, both `social` only, confirmed and hashed like the other fields (`false` and no format leave the hash unchanged). `format.cta` must be an https official link of the marketing profile inside the policy's allowed origins (`LINK_NOT_ALLOWED` or `FORMAT_CTA_NOT_OFFICIAL_LINK`, 409, at proposal, change, confirmation and resume). `GET …/assignments` items, the `assignment.confirm` inbox summary and the chat card carry `sharedAcrossChannels` and `format` (when set); `assignment_list` carries both (`format` null when unset). A shared run's content copies carry `sharedFrom: {contentId, contentVersion, bodyHash}` and appear per channel in `assignment-posts`, `assignment-drafts` and `run_status` like any other draft. New review codes: `FORMAT_LENGTH`, `FORMAT_HASHTAGS`, `AGENT_REVIEW_TEXT_CHANGED`; a shared text held back only on its own channel records `channelProblems` and `textApproved`, a rejected shared text `channels`. A format that does not fit a channel's limit with its link and image is refused with `FORMAT_EXCEEDS_CHANNEL_LIMIT` (409) at proposal, change, confirmation and resume.
