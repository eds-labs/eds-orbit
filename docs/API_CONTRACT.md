# Orbit API v1

Same-origin `/api` proxy. Session via Better Auth. Every modifying request requires Origin matching APP_ORIGIN; all project resources require membership. Owner can administer, editor creates/reviews content, viewer reads. No public signup. Setup needs installation token (`setupToken` input), owner email/name/password/workspaceName. Token is created only in local ignored runtime configuration.

- GET /api/setup `{configured:boolean}`; POST /api/setup `{name,email,password,workspaceName,setupToken}` -> `{configured:true}` then sign in.
- POST /api/auth/sign-in/email `{email,password}`; POST /api/auth/sign-out; GET /api/me -> `{user:{id,name,email},workspaces:[],projects:[]}`.
- GET /api/projects -> `{items: Project[]}`; POST `{name,timezone,language}` -> Project. Project fields id,workspaceId,name,timezone,language,mode,paused,generation.
- GET /api/projects/:projectId/modules any member -> `{switchable:boolean,modules:[{id,displayName:{en,de},version,dependsOn,enabled,explicit,changedBy,changedAt}]}` in dependency order (WP1.4, ADR 0009). `explicit:false` means the registry default applies. PUT /api/projects/:projectId/modules/:moduleId owner `{enabled:boolean}` -> the same body; answers 404 `NOT_FOUND` while `ORBIT_MODULES` is off, `MODULE_NOT_FOUND` (404) for an unknown module, `MODULE_DEPENDENCY_DISABLED` (409) when enabling a module whose dependency is off, `MODULE_REQUIRED` (409) when disabling a module an enabled module depends on. Every change writes the audit event `module.enabled` or `module.disabled`; nothing is deleted. While `ORBIT_MODULES` is on, activation is enforced (WP2.4, `docs/MODULE_ACTIVATION.md`): every route under `/api/projects/:projectId/` that a disabled module contributes, its actions (`POST …/actions/:name`) and its collections (`GET/POST …/:collection`) answer `MODULE_DISABLED` (404) after the membership check. With the flag off every module keeps working. New projects get the registry defaults recorded on creation.
- GET /api/projects/:projectId/dashboard -> `{project,counts,exceptions,publications,jobs,budget,readiness}`.
- GET /api/projects/:projectId/attention (any member; UI restructure §4.1) -> `{items, counts, status}`: what needs the member's attention. `items` are `{id, moduleId, kind, severity: "critical"|"warning"|"info", count?, dueAt?, since?, params, navKey, link}`, collected from every module that is enabled for the project and not hidden from the member (module role `none`), each read with the member's role in that module, plus the platform's own items; sorted by severity, then `dueAt` ascending (undated last), then `since` ascending, then `id`; at most 50. `counts` maps each `navKey` to the sum of `count ?? 1` over its items before the cap (an aggregated item adds its `count`). `status` is `{paused, mode?, aiMonth?: {spentMicros, limitMicros?}}`: `mode` is the project's mode (the `project.mode` of GET /dashboard that the marketing overview's mode band shows, set when a policy is activated; ruling R25), present only while marketing is enabled and visible to the member; `aiMonth` is present only for owners and editors (`platform.project.write`, the level of GET /ai-cost; ruling R26): `spentMicros` is the project's AI spend since the start of the UTC calendar month as the budget enforcement counts it (settled amounts plus reserved, in-flight and unclear reservations, released ones excluded), `limitMicros` the active policy's monthly limit, `null` when no active policy sets one, and absent when the policies are hidden from the member (module role `none`: unknown, not "no limit"). The platform's items are `platform_worker_down` (critical, no worker heartbeat within 30 s, any member), `platform_cost_unknown` (warning, owners, `params.micros` = unclear reservations this UTC month) and `platform_action_request` (warning, owners, aggregated open owner decisions, navKey `approvals`). Every object counts once in `counts`: a `marketing_exception` item stands for one open exception code (no `count`; `params.affected` = the resources it names, ruling R19); support lists at most five breached and five at-risk tickets and the rest of each kind as one item `support:sla:breached:more` / `support:sla:at_risk:more` (`count`, the earliest remaining `dueAt`, `params: {}`), and `support_unassigned` counts only unassigned tickets without an SLA item of their own (`params.othersListed: true` when some have one; no item when none are left; R20). `marketing_run_problem` (`RUN_FAILED`, `BUDGET_EXHAUSTED`) follows the agent activity's health rules (R21). The web renders the text from `kind` and `params`; `link` is an in-app path below `/p/:id`. Read-only, no audit row, `Cache-Control: no-store`. A module contribution that fails makes the whole read answer 500 `REQUEST_FAILED` (logged with the module id) rather than leaving its items out. The web shell reads it as `/attention?revision=<workspace revision>` (the server ignores the query; it only separates revisions) and reuses a response per project and revision for 30 s across navigations (ruling R15); a `navKey` is the route key of a sidebar entry, so `counts` are the badges, and a `navKey` without a visible entry (such as `approvals` while marketing is off) shows no badge. A kind the web does not know renders as a generic row (module name, kind, "Open"), so new kinds are additive.
- GET /api/projects/:projectId/:collection -> `{items: Entity[]}`. Entity `{id,kind,version,data,createdAt,updatedAt}`. Collection names in packages/schemas/src/index.ts.
- POST /api/projects/:projectId/sources with schema `source`; POST facts uses knowledge contract; POST missions with schema `mission`; POST content schema `content`; POST policies schema `policy`; POST metrics/preference/experiments corresponding schemas.
- PATCH /api/projects/:projectId/content/:id `{version,data:ContentInput}`; edits invalidate review and publication intents. Other generic writes forbidden.
- POST /api/projects/:projectId/actions/import `{sourceId,externalId,title,text,mimeType,language}` or `{sourceId,url}`. Inline text max 1 MB. Returns imported document.
- POST .../actions/retrieve `{query,language,purpose:'public'|'internal',at?}` -> EvidencePack entity or object.
- POST .../actions/revoke-source `{sourceId}` owner only; immediate tombstone and downstream invalidation.
- POST .../actions/run-mission `{missionId}` -> durable job. Local test drafts explicitly synthetic; live generation requires paid-test/automation budget.
- POST .../actions/review `{contentId,version}` -> server claim/evidence check.
- POST .../actions/approve `{contentId,version,packageHash}` owner only; obtain hash via POST .../actions/preflight `{contentId}`. No stale approvals.
- POST .../actions/publish `{contentId,version,scheduledAt?}` -> durable local intent; test executor never contacts external providers.
- POST .../actions/pause `{paused:boolean}` owner only; invalidates pending writes and exposes remote cancellation risk.
- POST .../actions/analyze `{campaign?:string}` -> deterministic aggregate-backed insight and bounded follow-up.
- POST .../actions/retry `{jobId}` editor/owner; bounded recovery only.
- POST .../actions/asset-status owner `{assetId,version,assetStatus:"approved"|"reference"|"outdated",confirmUsageRights?:boolean,providerUse?:boolean}` -> asset. Approving needs `confirmUsageRights:true` (`ASSET_RIGHTS_CONFIRMATION_REQUIRED`); `version` must be the asset's current one (`VERSION_CONFLICT`). `providerUse` ("May be sent to AI providers", default `false`) allows the asset's bytes to be sent to an AI provider (reference images, the Creative Studio's vision review); only an approved asset can have it (`ASSET_NOT_APPROVED` for `providerUse:true` with another status). Left out, an asset that stays approved keeps its stored value; taking the approval back or outdating the asset ends it, and approving again starts without it. A change is audited as `asset.provider_use_update`. The web offers it to owners only while `ORBIT_CREATIVE_STUDIO` is on (Brand asset library, Brand kit).
- POST .../actions/add-member `{email,name,password,role:'owner'|'editor'|'viewer'}` owner -> `{added:true}`. Creates the account when the address is unknown (name/password are ignored for an existing account) and adds it to the workspace as viewer and to the project with `role`. A project owner who does not own the workspace may add only new accounts or existing workspace members, only as editor/viewer, and may not change an existing owner's role; otherwise `WORKSPACE_OWNER_REQUIRED` (403) before anything is created. Every addition writes the project audit event `project_member.add` (resource: user ID; metadata `{role,previousRole,createdUser}`, no e-mail address). No member removal endpoint yet.
- GET .../export -> project export omitting secrets; GET .../content/:id/export -> article/markdown.
- GET .../knowledge-health -> conflicts,expiredFacts,failedImports,staleSources,missingEvidence,impacts (real data).
- POST .../actions/connector `{provider:'postiz'|'matomo'|'slack',baseUrl?,credential,siteId?,channelId?}` owner; encrypted server-side. GET connectors never returns credential. POST .../actions/connector-health `{connectorId}` owner triggers read-only capability check.

- GET /api/projects/:projectId/agent-runs?cursor&kind editor/owner -> `{runs:[{id,kind,agentName,taskClass,subjectType,subjectId,missionId,status,errorCode,startedAt,durationMs,modelCalls,toolCalls,inputTokens,cachedTokens,cacheWriteTokens,outputTokens,reasoningTokens,costMicros}],nextCursor}`. Newest first, 50 per page; `cursor` is the last run ID of the previous page (`INVALID_CURSOR` if unknown in the project); `kind` is `chat|generation|retrieval|ingestion|reindex|evaluation|image`. Token sums and `costMicros` (string) aggregate the run's spans; no prompts, outputs or provider text are returned.
- GET /api/projects/:projectId/ai-budget editor/owner -> `{providers:{anthropic:{configured,budget,level,spend,creditSync:"manual"}}}`: the project's Claude credit budget. `budget` is the saved `providerBudgets.anthropic` (or `null`), `level` one of `ok`, `warn`, `warn2`, `stopped` (or `null`), `spend` the current billing period's reservations of Anthropic models as the stop counts them (`spentMicros`, `settledMicros`, `pendingMicros`, `unknownMicros` as strings, `count`, `periodStart`, `periodEnd`). `creditSync` is always `manual`: the balance is the owner's verified value, not read from Anthropic. No key, no prompt content.
- GET /api/projects/:projectId/ai-cost?from&to&groupBy editor/owner -> `{from,to,groupBy,rows:[{key,reservedMicros,settledMicros,unknownMicros,count}]}`. `from`/`to` are ISO datetimes (default: start of current UTC month to now); `groupBy` is `day` (UTC date, default), `category`, `model`, `taskClass`, `mission` or `provider` (`openai`/`anthropic`, derived from the reservation's model through the project's model registry, else the `claude-` prefix; `null` without a model). Amounts are USD micros as strings; released reservations are excluded; `key` is `null` for unattributed rows. Errors: `INVALID_RANGE` (to not after from), `RANGE_TOO_LARGE` (over 93 days).
- POST /api/projects/:projectId/chat/packages/:id/attach-image editor/owner (the package's requester) `{deliverableKeys:string[1..4],acceptQaFindings?:true}` -> package snapshot. Attaches the package's generated image to the chosen drafts after an owner approved its usage rights; each draft is reviewed again and approvals or publications of its previous version are blocked. Errors `ASSET_RIGHTS_REQUIRED`, `DRAFT_REUSED` (the draft was reused from another package; revise it first), `IMAGE_NOT_GENERATED`, `PACKAGE_IMAGE_REQUIRED`, `CAPTION_TOO_LONG`, `ALREADY_SCHEDULED`, `DRAFT_SUPERSEDED`, `REVISION_IN_PROGRESS`, `CONTENT_PACKAGES_DISABLED`; none of the chosen drafts change on an error. Package snapshots report `image.rightsApproved`, `image.assetVersion` and `content.assetId`. With `ORBIT_CREATIVE_STUDIO` on, the project opted in to automatic creatives (`visualIdentity.creative.enabled`) and a primary logo in the brand kit, a chosen draft with `creativeCopy` gets its own composed creative (a rendition in its channel's format, bound to the package) instead of the raw image, and the response adds `creative:{composed:[contentId],skipped:[{contentId,code}]}`. A draft without image copy keeps the raw image and is listed with `CREATIVE_COPY_MISSING`; when the brand kit cannot compose (for example a logo that is no longer approved) the drafts with copy keep the raw image too and are listed with the brand kit's code (`APPROVED_LOGO_ASSET_REQUIRED`, `MARKETING_PROFILE_INVALID`); without a primary logo the raw image is attached and nothing is listed. The optional `acceptQaFindings:true` (owner only, `OWNER_REQUIRED` for an editor; with `ORBIT_CREATIVE_STUDIO` off the key is refused with `VALIDATION_FAILED` as before) accepts the findings of creatives that did not pass their checks, image copy findings included (audited as `creative.qa_override`); without it such a creative refuses the whole attach with `CREATIVE_QA_FAILED`. A raw image replaces a creative the draft carried (the creative is superseded, its rendition outdated). Further errors with the studio on: `MARKETING_PROFILE_REQUIRED`, `MARKETING_PROFILE_INVALID`, `CREATIVE_QA_FAILED`, `CREATIVE_TEXT_TOO_LONG`, `CREATIVE_TEXT_UNSAFE`, `CREATIVE_LINK_NOT_ALLOWED`, `TEXT_OVERFLOW`, `LOGO_INTEGRITY`, `SCREENSHOT_INTEGRITY`, `ASSET_RIGHTS`, `MARKETING_PROFILE_CHANGED`, `BRAND_ASSET_CHANGED`, `BRAND_ASSET_INTEGRITY_FAILED`, `CONTENT_CHANGED`, `CREATIVE_NOT_ATTACHABLE`, `CREATIVE_RIGHTS_REQUIRED`, `OWNER_REQUIRED`; again none of the chosen drafts change.
- POST /api/projects/:projectId/chat/packages/:id/unschedule editor/owner (the package's requester or an owner; not gated by `ORBIT_CONTENT_PACKAGES`) `{deliverableKey}` -> `{result,publicationStatus,package}` with `result` `canceled|withdrawn|handoff_in_progress|not_retractable|nothing_scheduled`. Withdraws open schedule proposals and takes the publication back before the handoff; a handed-over post is reported, never retracted. Package snapshots report a pending move as `schedule.move:{status,scheduledAt,actionRequestId}`.
- GET /api/projects/:projectId/action-requests owner -> `{items:[{id,version,actionType,riskClass,packageHash,costCeilingMicros,expiresAt,createdAt,requestedBy,summary:{prompt,model,maxCostMicros,size,quality,channel,scheduledAt,body,executionMode,assetId,packageGoal}}]}`. Pending, unexpired requests whose action type needs an owner decision (`image.generate`, `content.schedule`), newest first, at most 50. A `content.schedule` item shows the exact post text, channel, slot and execution mode.
- POST /api/projects/:projectId/action-requests/:id/decide editor/owner `{version,packageHash,decision:"approve"|"reject"}` -> `{id,version,status}`. Decides one exact action request (ADR 0008 addendum). The action type sets the deciding role (`image.generate` and `content.schedule`: owner; `content_package.start`: the requesting editor or owner) and rechecks its payload; errors `ACTION_REQUEST_STALE`, `ACTION_REQUEST_EXPIRED`, `ACTION_REQUEST_NOT_PENDING`, `OWNER_REQUIRED`, `PACKAGE_STALE`, `SCHEDULE_STALE`, `SCHEDULE_SLOT_TAKEN`, `CONTENT_PACKAGES_DISABLED`, or a preflight blocker of the scheduled post (the decision is then not recorded). A repeated identical decision returns the recorded result. Conversation detail (`GET …/chat/conversations/:id`) additionally returns `packages` for the requesting user: `{id,version,goal,status,ceilingMicros,image,actionRequest,deliverables:[{key,channelId,channelName,platform,plannedSlotAt,status,errorCode,content,review,schedule}]}`; `schedule` is null or `{status,scheduledAt,contentId,actionRequestId,executionMode,publicationId,blockers}` with status `awaiting_approval|stale|expired|rejected|canceled` before the decision and `scheduled` or the publication status after it; `image` is `{prompt,maxCostMicros,status,assetId,href,errorCode}` with status `planned|awaiting_approval|queued|running|generated|outcome_unknown|failed|canceled`.
- POST /api/projects/:projectId/chat/packages/:id/cancel editor/owner, requester only -> package snapshot with status `canceled`. Withdraws the start or image decision, cancels queued jobs and archives missions without a draft; drafts, running jobs and already sent requests are reported as they are. `NOT_FOUND` for another user's package.

## Creative Studio

Creative Studio (`ORBIT_CREATIVE_STUDIO=true`; with it off every route below answers 404 `NOT_FOUND`, and while Marketing is off for the project `MODULE_DISABLED`). Request bodies are strict: an unknown or malformed field is `VALIDATION_FAILED` (400), and no body can choose how a creative is attached. A creative is `{id, version, createdAt, updatedAt, contentId, template, variant, options, copy, brief, components, renditions:[{format, variant?, channel?, assetId, width, height, bytes, sha256, href}], qa:{checks, vision?, verdict}, corrections, cost, status}`. `status` (`composed|needs_owner|needs_rights|attached|superseded`) is where the creative is in its life, `qa.verdict` (`pass|corrected|needs_owner`) how good it is; an attached creative with findings keeps `status: "attached"` and shows `qa.verdict: "needs_owner"`.

- GET /api/projects/:projectId/creative/options (any member) -> `{templates:[{id, variants:{<format>:[variant]}, needs:{art,product}, copyLimits:{eyebrow,headline,subline,cta}}], formats, defaultChannelFormats, config}`: the seven templates with the variants each format offers, the four formats and the channel defaults. `config` is the project's resolved creative settings (`enabledTemplates`, `defaultVariants`, `formatsByChannel`, `logoPlacement`, `ctaStyle`, `maxArtCorrections`, `visualReview`) or `null` while its brand kit cannot compose (no profile, no primary logo, an unusable logo).
- POST /api/projects/:projectId/creatives editor/owner `{contentId, template?, variant?, copy?:{eyebrow?,headline,subline?,cta?}, artAssetId?, productAssetIds?, options?:{logoPlacement?,textScale?}, generateArt?:{confirmMaximumCostMicros, confirmPromptMayBeSentToProvider:true, requestId?}}` -> 201 creative. A manual request: an explicit variant the format does not offer is `CREATIVE_VARIANT_NOT_AVAILABLE` and an explicit template that needs products without approved products `PRODUCT_ASSET_REQUIRED` (409), never a silent replacement. Without `copy` the post's `creativeCopy` is used (`CREATIVE_COPY_REQUIRED`). `generateArt` is owner only (`OWNER_REQUIRED`, 403) and cannot be combined with `artAssetId`: one paid image at the confirmed per-image ceiling (`IMAGE_COST_CONFIRMATION_STALE` when it is no longer the configured one), after a free trial composition has refused what no art can fix; the art is stored unapproved and the creative is `needs_rights` until the owner approves it and recomposes. Requests with `generateArt` are limited to 3 a minute per client in their own bucket; every request also counts against the client's write limit. The image copy follows the banner copy rules: invisible or look-alike characters (`CREATIVE_TEXT_UNSAFE`) and links (`CREATIVE_LINK_NOT_ALLOWED`) are refused with 409 and `detail.codes`; a figure, number word, price or status word, a promise or prohibited wording, or a bare host is composed as a failed blocker (`CREATIVE_UNSUPPORTED_CLAIM`, `CREATIVE_PROHIBITED_LANGUAGE`, `LINK_UNVERIFIED` in `qa.checks`), so the creative `needs_owner`; a CTA is exempt only when it is the post's mission CTA. The same holds for a recomposition's copy. The optional `requestId` (uuid) is the image request's id: sending the same request again is `RESERVATION_ALREADY_USED` (409) instead of a second payment. Further errors: `NOT_FOUND`, `CREATIVE_SOCIAL_ONLY`, `CREATIVE_TEXT_TOO_LONG`, `CREATIVE_TEXT_UNSAFE`, `CREATIVE_LINK_NOT_ALLOWED`, `ART_REQUIRED`, `INVALID_TEMPLATE_INPUT`, `TEXT_OVERFLOW`, `LOGO_INTEGRITY`, `SCREENSHOT_INTEGRITY`, `ASSET_RIGHTS`, `MARKETING_PROFILE_REQUIRED`, `PRIMARY_LOGO_REQUIRED`, `APPROVED_LOGO_ASSET_REQUIRED`, `MARKETING_PROFILE_CHANGED`, `BRAND_ASSET_CHANGED`, `CONTENT_CHANGED`; nothing is stored on an error, except that a failure after the image was paid names the art in `detail.artAssetId` and keeps it as an unapproved reference.
- GET /api/projects/:projectId/creatives/:creativeId (any member) -> creative; `NOT_FOUND` for another project's or a malformed id.
- GET /api/projects/:projectId/content/:contentId/creative (any member) -> the post's newest creative that is not `superseded`, or `null`; `NOT_FOUND` for a post that is not in the project.
- POST /api/projects/:projectId/creatives/:creativeId/recompose editor/owner `{template?, variant?, options?, copy?}` (an empty or missing body recomposes with the current brand kit) -> creative. Free: the same art and products (the bytes they were composed from, else `BRAND_ASSET_CHANGED`) with another template, variant, logo placement, text scale or copy. The new renditions replace the old ones; the rendition the post carries stays until the next attach.
- POST /api/projects/:projectId/creatives/:creativeId/regenerate-art owner `{confirmMaximumCostMicros, confirmPromptMayBeSentToProvider:true, requestId?, correction?:{kind:"subject_larger"|"calm_text_zone"|"more_detail", note?}}` -> creative. Replaces the art with new Orbit art (one paid image, 3 a minute per client); at most the brand kit's `maxArtCorrections` attempts per creative (`ART_CORRECTION_LIMIT`, 409, before anything is reserved), every sent attempt counts. The creative becomes `needs_rights` until the owner approves the new art and recomposes. `requestId` as for creating; a retried request leaves the creative's attempts and cost as the one payment made them.
- POST /api/projects/:projectId/creatives/:creativeId/review owner `{}` (3 a minute per client) -> creative with `qa.vision`. The optional vision review of the first format's rendition: `CREATIVE_NOT_REVIEWABLE` (a `superseded` creative or one that `needs_rights`, before anything is reserved), `VISION_REVIEW_DISABLED`, `PROVIDER_USE_REQUIRED`, `PROJECT_PAUSED` (409) and the spend mandate's refusals; a rendition that was judged already returns its stored verdict without a second payment.
- POST /api/projects/:projectId/creatives/:creativeId/attach editor/owner `{acceptQaFindings?:true}` -> `{contentId, assetId}`. Puts the rendition in the post's channel format on the post (the post goes back to `draft`, loses an agent's review, CS-D7, and is reviewed again). A creative that `needs_owner` needs `acceptQaFindings: true` from an owner (`CREATIVE_QA_FAILED` without it, `OWNER_REQUIRED` for an editor); integrity and rights findings are never accepted. Further errors: `CREATIVE_RIGHTS_REQUIRED`, `CREATIVE_NOT_ATTACHABLE`, `CONTENT_CHANGED`, `DRAFT_SUPERSEDED`, `ALREADY_SCHEDULED`, `CAPTION_TOO_LONG`, `BRAND_ASSET_CHANGED`, `ASSET_RIGHTS`, `LOGO_INTEGRITY`, `SCREENSHOT_INTEGRITY`. Repeating the attach changes nothing.

## Errors

Errors `{error:{code,message}}`, no stack, provider text, source snippets or SQL. An error that names what it refused adds `detail`, an object of ids and codes only (never content or secrets): `{assetIds,reasons}` (comma-separated) for `ASSET_RIGHTS`, `{failed:[{contentId,codes}]}` for a package's `CREATIVE_QA_FAILED`, `{codes}` (comma-separated) for refused image copy (`CREATIVE_TEXT_TOO_LONG`, `CREATIVE_TEXT_UNSAFE`, `CREATIVE_LINK_NOT_ALLOWED`), `{artAssetId}` for a failure after a paid image; other errors have none. Specific shapes are validated server-side and generated OpenAPI supplements this contract (it declares `code` and `message` only).

`GET /api/projects/:projectId/indexes` returns owner-visible generation/evaluation state. Read collections include `calendar_blocks`, `community_questions`, `community_groups`, `work_packages`, `followup_plans`, `connector_verifications` and `index_evaluations`. Index evaluation query inputs are private project data, not public content.

`POST /api/workspaces/:workspaceId/pause {paused}` requires a current workspace owner and atomically fences all current projects before per-project reconciliation. Resuming does not restore invalidated approvals or intents. New projects start in Observe.

`POST /api/slack/:workspaceId/:projectId/interactions` is one of two write routes exempted from browser Origin checking: it requires the exact raw signed body, current timestamp, replay protection, team/channel and current mapped-owner authorization. It returns no sensitive details.

Orbit Telegram bot (Orbit Agents, `ORBIT_AGENTS=true`; every route answers 404 while it is off): `GET /api/projects/:projectId/telegram` → `{status, linkedAt}`, `POST .../telegram/connect {token}` → `{linkCode, expiresAt}` (10 min, single use) and `POST .../telegram/disconnect` are owner-only. The bot token is stored encrypted and never returned; `telegram_connections` is not a readable collection and is excluded from the project export. `POST /api/telegram/:projectId/:connectionId` is the second Origin-exempt write route: Telegram's webhook, authenticated by the per-connection `X-Telegram-Bot-Api-Secret-Token` (only its hash is stored; a wrong one gets 401 and an audit event) and the bound private chat. An unknown project, an unknown connection or another project's connection gets the same 401. The bot counts as connected only while the user it is bound to is still a project owner. It handles `/start <code>`, Stop (`stop:` callback, withdraws an assignment post before handoff) and `/pause` with an inline confirmation; resuming is only possible in Orbit.

Orbit Agents assignments (`ORBIT_AGENTS=true`; every route answers 404 while it is off, before authentication):

- `GET /api/projects/:projectId/assignments` (any member) → `{timezone, paused, items}`. Each item has `id, version, name, status, kind, contentType, channels, channelNames, schedule, image, vetoMinutes`, `nextRunAt` (when the next run starts preparing; null when none is due, the assignment is not active or the project is paused), `monthCostMicros` (this UTC month, counted like the budget check: settled reservations at their cost, open ones at their reserved amount) against `monthlyBudgetMicros`, and `actionRequestId` (the open `assignment.confirm` request of a draft, else null). Ended assignments come last. The route replaces the generic `assignments` collection read. - `POST /api/projects/:projectId/assignments/:id/status {status: "paused"|"active"|"ended", version}` → `{id, version, status}`. Editors pause and end; only an owner resumes (`OWNER_REQUIRED`); viewers get 403. A version other than the current one is `VERSION_CONFLICT`. Content and time changes go through the Orbit chat and a new confirmation.
- `GET /api/projects/:projectId/assignment-posts` (any member) → `{items}`: assignment posts Orbit still holds (`intent_created`, or `blocked_dependency` before any handoff), earliest slot first, with `id, version, status, reason, channel, channelName, scheduledAt, vetoDeadline, excerpt` (280 characters), `assignmentId, assignmentName`. - `POST /api/projects/:projectId/publications/:id/veto {version, reason?}` (editor or owner) → `{result: "vetoed"|"already_handed_over"|"not_found"}`: the same Stop as the bot's button (source `orbit`). A post Postiz already has answers `already_handed_over` and stays unchanged; a reason is kept as a proposed preference. Posts the owner released (below) can be stopped the same way.
- `GET /api/projects/:projectId/assignment-drafts` (any member) → `{items}`: assignment drafts that wait for the owner's release (social drafts left `needs_review` by the review, without a linked bot or while agent review authority is off), of runs that are not canceled, whose assignment's confirmation still covers them and whose run slot is today or later, earliest first, with `id, version, channel, channelName, slotAt, excerpt` (280 characters), `assignmentId, assignmentName`, `agentApproved` (the review agent approved the text) and `problems` (codes the review left open).

Records the owner's content review, lets the draft's mission publish exactly this post, records the package approval in assisted mode and schedules it through the publisher without a veto window at its run slot (`requestedAt`), or at the next free half hour that day when the slot is taken or has passed (`scheduledAt`). Refusals (409, nothing changes): `SLOT_UNAVAILABLE`, `VERSION_CONFLICT`, `DRAFT_NOT_AWAITING_OWNER`, `DRAFT_NOT_PUBLISHABLE` (blog or newsletter), `ASSIGNMENT_NOT_CONFIRMED`, `RUN_CANCELED`, `POLICY_REQUIRED`, or the preflight blockers joined by commas. Not an assignment draft: 404. A second release answers `already_released` with the same publication.

- Delivery as Postiz drafts (R73): assignment content has `delivery: "publish"|"postiz_draft"` (absent = `publish`; confirmed and hashed like the other fields; `postiz_draft` only for `social`, and refused with `POSTIZ_DRAFTS_DISABLED` (409) while `ENABLE_POSTIZ_DRAFTS` is off). `GET …/assignments` items, the `assignment.confirm` inbox summary and the chat card carry `delivery`. `GET …/assignment-posts` items carry `delivery`; items with `delivery: "postiz_draft"` are the assignment's Postiz draft handoffs whose slot is ahead (`id`, `version`, `status` = `queued`|`sending`|`accepted`|`outcome_unknown` of the handoff, `scheduledAt` = its slot, `vetoDeadline` null) and cannot be stopped (the veto route answers `not_found` for them). `GET …/assignment-drafts` items carry `delivery`.
