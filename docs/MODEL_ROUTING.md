# Model routing and cost contract

Since 2026-10-19 Orbit has two runtime text providers, OpenAI and Anthropic (Claude); see "Anthropic Claude provider" at the end. The following paragraphs describe the OpenAI contract, which is unchanged; images and embeddings stay on OpenAI.

OpenAI was the only runtime AI provider until then. Every paid text call resolves a task-class route in `packages/ai/src/routing.ts` (see "Task-class routes" below). Without a configured route, the legacy tier table applies (default in `packages/config/src/index.ts`, owner-editable as `modelRoutes`): `gpt-5.6-terra` (standard) for chat and routine drafts, `gpt-5.6-sol` (quality) for blog drafts. The table also names `gpt-5.6-luna` (fast) and one `gpt-6-astra` escalation, but no caller uses them: unresolved quality issues go to review, and nothing spends on an Astra escalation automatically. No `ultra` production API parameter is used.

Public model documentation does not prove account availability. Runtime calls require an application-owned OpenAI credential, an explicit verified-model allowlist and a dated rate card. Owners can manage these values in Orbit Settings; the key is encrypted server-side with `CREDENTIAL_KEY`, is never returned through the API or UI, and takes effect for new jobs without a redeploy. Existing `OPENAI_API_KEY`, `OPENAI_VERIFIED_MODELS` and `OPENAI_RATE_CARD_JSON` remain a local bootstrap fallback only when no Orbit configuration has been saved. Rates are integer USD micros per million input/output tokens, stay valid until the owner changes them (no expiry since 2026-10-02), and are not assumed from a fixed monthly estimate. No account credential was borrowed from Codex/ChatGPT, and no paid call was authorized or executed during implementation.

Image generation is a separate capability. Orbit supports the current GPT Image 2.5 API model IDs `gpt-image-2.5-flare` (default) and `gpt-image-2.5-sunburst`, including their pinned `2026-09-08` snapshots. An owner may save a dedicated image API key in the same configuration UI; it is encrypted independently and never returned. If absent, the explicitly configured shared OpenAI key is used. Environment variables are bootstrap fallbacks only. Enabling images requires the selected model in the verified-model allowlist, a non-zero per-image reservation ceiling with a verification timestamp (it does not expire), an active project policy, available daily/monthly/run budget, and exact owner confirmation for each prompt and ceiling. Generated assets start as `reference` and cannot be used until an owner separately approves rights and brand fit.

The image request sends the owner's prompt plus the project palette and bounded design rules to OpenAI. It instructs the model not to generate logos, trademarks, UI screenshots or readable copy; approved logos and copy are composed locally by the deterministic renderer. The raw prompt is not retained by Orbit after the call; only its hash and the derived provider-prompt hash are stored. The provider response is normalized to a metadata-stripped PNG and stored project-scoped with model, dimensions, usage when returned and reservation provenance. Because the image response does not provide a safely computable charge in the current adapter, the conservative reservation remains `unknown` and counted rather than being treated as zero. No live image call was made during implementation.

Draft generation uses OpenAI Responses API through the pinned SDK (`openai` 7.25.0), `store:false`, no model tools, strict structured output, no automatic SDK retries, a 45-second timeout and the route's output-token ceiling (default 1800). Orbit Chat is the only path with model tools: read tools plus the draft-only `propose_campaign` tool and, with `ORBIT_CONTENT_PACKAGES`, the content package tools, streamed, `store:false`, no automatic retries (see `ORBIT_CHAT_V1.md`). A package revision adds a `revision` block (instruction and previous body) to the draft contract; the draft instructions say it changes only what is asked and never authorizes new claims. A draft of an assignment run (Orbit Agents) adds a `brief` block from the strategy step (topic, angle, cta, notARepeatBecause) together with the run's other drafts and recent channel posts; the instructions say the brief never authorizes claims beyond the supplied facts. Its calls reserve under the copywriter task (`agent:<taskId>:copy:<briefKey>`, retrieval `query:mission:agent:<taskId>:…`) with the run key `assignment-run:<runId>`; the run's image reserves under `image:agent:<taskId>:image`. By default (`ORBIT_IMAGE_REFERENCES=false`) the image prompt carries a style description derived once from the assignment's approved style references (stored in `assignment_style_descriptions`); with `ORBIT_IMAGE_REFERENCES=true` the references themselves go to `images.edit`, which is verified from the SDK types only until the first budgeted live call. If no reference can be read, the description is used.

Imported evidence is marked untrusted. All factual claims are checked separately against current evidence before publication; a model cannot certify arbitrary extra text. Free editorial text requires owner review.

Query and document embeddings are separate calls and cost categories. Baseline is `text-embedding-3-small`/1536. The alternate large profile uses validated 1536/3072 dimensions. Profile, model, dimension, metric, chunker/retriever configuration and index generation are explicit. Model changes create separate immutable corpus manifests, bounded paid builds and evaluations, then explicit activation/rollback. A same-profile evaluated baseline checkpoint is required before an alternate profile replaces a legacy baseline. Live evaluation requires at least 60 cases (48 answerable and 12 negative), Recall@10 >= 0.90, zero forbidden hits, and exact settled build/evaluation receipts. It never activates itself.

Every call reserves before transmission under a serialized project transaction. The estimate includes exact serialized input bytes plus bounded protocol overhead and output ceiling. Query and text costs share the same work-package budget; build/evaluation batches share their run budget. Daily/monthly totals include in-flight and unknown amounts. Usage settlement commits before result attachment, so a concurrent source/policy withdrawal cannot erase a charge. A failed or interrupted call is not automatically considered free or safely repeatable.

Paid mocks exercise accounting, race handling and SQL attachment only. Genuine model availability, semantic embedding quality, latency and actual costs remain `BLOCKED_EXTERNAL` pending credentials and an approved bounded budget. `LIVE_RAG_EVAL_PASSED` is a deprecated configuration field and grants no authority; runtime reads the current database evaluation and its receipt/config/corpus bindings.

`store:false` does not establish zero data retention or fully local processing. Approved text/query bytes leave the host for OpenAI; account-specific retention terms must be reviewed by the operator. Public-use rights and external-model-use rights are independent.

Image prompts, palette values and design rules also leave the host after the per-request confirmation. The image endpoint does not claim zero retention. Do not place secrets, personal data, private customer material or unapproved source assets in an image prompt.

## Rate card v2 and cache-aware settlement (2026-09-30)

Each rate card entry has `inputMicrosPerMillion`, `outputMicrosPerMillion`, `verifiedAt` and two optional fields: `cachedInputMicrosPerMillion` (default: the input rate, so an omitted value never understates a cached read) and `cacheWriteMicrosPerMillion` (default: `ceil(1.25 x input rate)`, the documented cache-write multiplier). Existing cards stay valid without changes. Orbit Agents research adds a third optional field, `webSearchMicrosPerCall`: the fee of one hosted `web_search` call with that model (default 10,000 micros, USD 10 per 1,000 calls, the OpenAI list price when this was written; verify and set it in the rate card). It is added to the reservation (searches still allowed per call) and to the settled cost (one per `web_search_call` item); the search content tokens are billed as ordinary input. A fourth optional field, `webSearchInputTokensPerCall` (default 8,000), is the input-token allowance the reservation adds for the content of each search still allowed in the call, priced like the rest of the estimated input; the settled cost uses the reported usage, so the allowance only keeps a research call within its task, run and month ceilings before it is sent.

Settlement from the provider usage object, in USD micros, rounded up with a minimum of 1:

```
(ordinary x input + cached x cachedInput + cacheWrite x cacheWriteRate + output x outputRate) / 1,000,000
ordinary = input_tokens - cached_tokens - cache_write_tokens
```

Reasoning tokens are part of output tokens and are not charged twice. If the usage object lacks `cached_tokens` or `cache_write_tokens`, the split is unknown and all input tokens settle at `max(input rate, cache-write rate)` rather than being assumed cheap. Cached plus cache-write tokens greater than input tokens, or an unparseable usage object, fail with `USAGE_INCONSISTENT` or `USAGE_UNKNOWN`; the reservation then stays unknown and counted. An empty rate card fails with `VERIFIED_PRICE_CONFIGURATION_REQUIRED`; a missing model price fails with `CURRENT_PRICE_REQUIRED`. Prices do not expire; the owner updates the rate card when OpenAI changes a price.

The pre-transmission estimate cannot know the cache split, so it charges all input tokens at the cache-write rate (implicit caching may write any prompt). Reservation ceilings therefore rise by up to about 25 % of their input part compared with the earlier estimate; output-dominated calls change less. Chat proposal ceilings shown to the owner include this increase. Settled cost is what the usage actually incurred and is normally lower than the reservation; the difference is released on settlement.

Every paid reservation now also records `agentRunId`, `taskClass`, `model` and `missionId` (nullable) for attribution. A query embedding made while drafting keeps the draft task class, so a task class reports the full cost of producing a draft; the `category` still separates query-embedding from text rows. Read the breakdown through `GET /api/projects/:projectId/ai-cost` (see `API_CONTRACT.md` and `OPERATIONS.md`).

## Task-class routes (2026-10-01)

Three task classes reach a model: `chat_operator` (Orbit Chat), `draft_social` (every draft whose content type is not `blog`) and `draft_blog`. Each resolves to a route `{ model, reasoningEffort?, maxOutputTokens }`:

1. An explicit task route saved by the owner in the OpenAI configuration dialog (Settings, Project tab; sections "Chat operator route", "Social drafts route", "Blog drafts route") wins. An empty model field means no task route.
2. Otherwise the legacy tier applies: `chat_operator` and `draft_social` use the `standard` tier, `draft_blog` the `quality` tier, with the default ceilings 3,000 (chat) and 1,800 (drafts) and no reasoning parameter. With nothing saved, every task therefore uses the same model as before routing v2. The environment bootstrap fallback has no task routes.
3. The routed model must be in the verified-model allowlist. Saving an unverified route fails with `ROUTED_MODEL_NOT_VERIFIED`; a route that becomes unverified later fails closed at call time with `MODEL_CAPABILITY_NOT_VERIFIED` and never falls back to another model. The configuration view lists the effective route per task class, marks unverified ones and shows whether the routed model has a current price (a `missing` price makes runs fail closed with `CURRENT_PRICE_REQUIRED`).

Orbit Agents (2026-10-09) adds four specialist task classes with the same rules: `agent_strategy`, `agent_research` and `agent_analytics` default to the `standard` tier, `agent_review` to the `quality` tier, each with a 1,800-token ceiling; the dialog has a route section per class. The copywriter keeps `draft_social`/`draft_blog` and the visual the image route. A specialist call reserves under `agent:<taskId>:<n>` with category `agent_text` and the budget run key `assignment-run:<runId>`, so the policy's per-run ceiling applies to one assignment run. Before each reservation the assignment's own month spend (reservations under the run keys of its runs created in the current UTC month, settled at the settled amount, open at the reserved one) plus the estimate is checked against its `monthlyBudgetMicros`; only that check sets the assignment `budget_exhausted`, while project refusals from the policy (`BUDGET_EXCEEDED`, `RUN_BUDGET_EXCEEDED`) fail the task and leave the assignment active. `AgentRun.kind` is `agent` (migration `202610090001_agent_run_kind`, widens a check constraint only).

`reasoningEffort` is one of `none`, `low`, `medium`, `high`, `xhigh`, `max`. When it is omitted, the request carries no `reasoning` key and the model's own default applies. Not every model accepts every effort or ceiling; the provider then refuses the request and the run ends with `MODEL_REQUEST_NOT_ACCEPTED` (see below), so measure an effort in the eval before saving it. `maxOutputTokens` is bounded to 256–16,000 and includes reasoning tokens. Reservations always estimate with the route's `maxOutputTokens`, so a larger ceiling raises every reservation for that task class and can turn into budget refusals. Chat proposals price the first draft with the route of its content type: a blog proposal is priced with `draft_blog`.

Route version: the entity version of the saved OpenAI configuration is the route version. Every `AgentRun` stores it in `routeVersion` (migration `202610010001_agent_run_route_version`, additive; null for the environment fallback). The `agent-runs` endpoint does not return it yet; read it from the database for eval or incident analysis. A run keeps the version it started with. If the configuration is saved while a run is in progress (any save, including image-only settings), the run stops before its next paid call: generation with `GENERATION_DEPENDENCY_CHANGED`, chat with `CHAT_ROUTE_CHANGED`. Nothing is transmitted on the new configuration under the old version; start the run again.

A response that completed with usage but whose output is unusable (invalid JSON or schema: `MODEL_OUTPUT_NOT_VALID`; empty body, the model abstained: `MODEL_EVIDENCE_ABSTENTION`) settles its known cost. `INSUFFICIENT_EVIDENCE` is reserved for the free evidence failure before any model call; only that code lets an owner start the one-time live-draft recovery, so a paid abstention is never offered as recoverable. A request the provider refuses with HTTP 400, 401, 403, 404, 422 or 429 (for example an unsupported reasoning effort, an invalid key or a rate limit) was not processed and is not billed: its reservation settles at 0 and the run ends with `MODEL_REQUEST_NOT_ACCEPTED`, which is not retried automatically. Only transport errors, timeouts, other HTTP statuses, errors inside a started stream and missing usage leave the reservation `unknown`. `MODEL_OUTPUT_NOT_VALID` is not retried automatically.

**Standard models and presets (2026-10-25, `ORBIT_AI_DEFAULTS`).**
- **Presets.** A preset (`packages/ai/src/presets.ts`) sets the default provider and its tier models from a provider and a level; the tier per task class stays as above.
- **Organization standard.** An organization's standard (AI profile `defaults`) replaces the profile's default provider, tiers and task routes for projects without own settings.
- **Project choice.** A project with `routing.source = "organization"` takes the standard's provider, tiers and task routes, and its `overrides` win per task. With `"preset"` it uses its own preset plus `overrides`. Without `routing`, its saved settings apply unchanged.
- **Verification.** Every preset model and override must be active in the catalog when saved; at call time an inactive model fails closed as usual.

Switching a route (for example to `gpt-6-luna` or `gpt-6.1-sol`) requires a current generation eval report (see `evals/generation/README.md`; reports are written to `docs/evidence/`) that shows an acceptable review pass rate, cost and latency for the candidate, then an owner save of the route. The switch applies to new runs only. Roll back by saving the previous route or removing the task route (legacy tier again).

Official references checked on 2026-09-19: [GPT Image 2.5 Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare), [GPT Image 2.5 Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst), and [Images API generate](https://developers.openai.com/api/reference/cli/resources/images/methods/generate).

## Anthropic Claude provider (2026-10-19)

Plan and architecture report: `docs/superpowers/plans/2026-10-19-anthropic-provider.md` (decisions D-A1 to D-A12). Orbit calls the Claude Messages API through the official SDK (`@anthropic-ai/sdk` 0.135.0, pinned) behind the same functions every caller already uses (`generate`, `streamChat`, `respond` in `packages/ai`): the route's model decides the provider, so Orbit Chat, the Orbit Agents specialists, support triage and drafts and the draft pipeline run on Claude when their route names a Claude model. No caller imports a provider SDK.

**Provider of a model.** The owner's model registry entry (`models[id].provider`) wins; otherwise a model id starting with `claude-` is Anthropic and everything else OpenAI. The verified-model allowlist, the rate card and the task routes apply to both providers exactly as before: an unverified or unpriced Claude model fails closed (`MODEL_CAPABILITY_NOT_VERIFIED`, `CURRENT_PRICE_REQUIRED`).

**Configuration.** The same per-project configuration entity (`openai_configuration`) carries the provider fields, saved by the owner action `ai-provider-configure` (Settings → AI): the encrypted Anthropic key, `defaultProvider` (`openai` by default), the Anthropic tier models (`anthropicTierRoutes`: fast, standard, quality; used for task classes without an explicit route only while `defaultProvider` is `anthropic`), the model registry (provider, display name, capabilities, note), the provider budget and the fallback setting. Every save bumps the route version like the OpenAI dialog does. `ANTHROPIC_API_KEY` and `AI_DEFAULT_PROVIDER` are environment bootstrap fallbacks only.

**Key resolution as built (verified 2026-10-24).** For each provider a call uses the project's saved key first, then a key granted through a central connection (ADR 0014). The environment applies differently per provider:
- `OPENAI_API_KEY` (and the image key) only while the project has no saved configuration (`central-ai.ts`, `runtimeOpenAiConfiguration`). A project that saved Claude settings without an OpenAI key therefore has no OpenAI key, even when the environment has one: OpenAI-routed tasks, embeddings and image generation fail there with `PAID_CALL_NOT_AUTHORIZED` / `EMBEDDING_NOT_AUTHORIZED`.
- `ANTHROPIC_API_KEY` applies even after a save.

Settings → AI, the MCP model view and readiness report key presence by this same rule (`effectiveAiStatus`), and list the task classes whose routed provider has no key (`routesWithoutKey`). **Key rule v2 (decision E-1b, built, off by default).** With `ORBIT_AI_KEY_RULE_V2=true`, the environment is a bootstrap only for projects without a saved configuration, for both providers. The Anthropic environment key then ends with a save, as the OpenAI key does today.
- A first save under v2 needs a key the project keeps: its own, or a granted connection.
- Before turning the flag on, run `node scripts/ai-key-rule-report.ts` in the api container. Per project it lists the key sources today and after the switch, the keys the project would lose (`lostKeys`), and whether chat and drafting still run. Set up a project key or a grant for every row with `actionRequired`.

**Without an OpenAI key (decisions E-8, E-9).** Anthropic offers no embedding model and no image generation, so a project with only a Claude key:
- runs text normally;
- searches knowledge full-text: no document embedding is attempted and nothing is reserved; queueing, reindexing and index evaluation refuse with `EMBEDDING_KEY_REQUIRED`;
- has image generation off.

Settings → AI & budget and `ai_models_get` show this as `capabilities: { text, search: "semantic" | "full_text", images }`.

**Provider budgets (phase 3.4).** `providerBudgets` takes `openai` as well as `anthropic`. `reserve`, `GET /ai-budget` and the attention item cover both. An organization or system AI profile may hold provider budgets; a project inherits one for each provider it sets none for.

**One save path (phase 3.2).** The owner action `ai-configure` (`{ models?, providers? }`) saves both sections of the configuration in one transaction with one audit entry. `openai-configure` and `ai-provider-configure` remain as aliases.

**Suggested models (not defaults).** `packages/ai/src/provider.ts` ships a dated suggestion (`anthropicCatalog`, read from the official model and pricing pages on 2026-10-19): `claude-haiku-5-5` (USD 0.10 / 0.50 per million input / output tokens, cache read 0.01, cache write 0.125; prompts up to 100,000 tokens), `claude-sonnet-5-5` (2 / 10, cache read 0.10, write 2.50), `claude-opus-5-5` (4 / 20, cache read 0.20, write 5), web search USD 10 per 1,000 searches, with the tiers fast = Haiku, standard = Sonnet, quality = Opus and the start routes of the request (chat, drafts, research, review: Sonnet; strategy: Opus; analytics and support triage: Haiku). The Claude dialog can add them to the verified models and the rate card; nothing is used until the owner saves it, and the owner updates the prices when Anthropic changes them. Existing routes are never overwritten by the suggestion.

**Request shape.** System prompt and the conversation prefix carry `cache_control: ephemeral` (5-minute cache), `max_tokens` is the route's ceiling, `reasoningEffort` becomes `output_config.effort` (`none` is refused for Claude models at save and call time: `ROUTE_EFFORT_UNSUPPORTED`), thinking stays at the model's adaptive default, tools are sent without `strict` and with their full schemas, bounds included (Anthropic refused Orbit's tool set as a too large compiled grammar; Orbit's services validate every tool input), no tool is forced, no prefill, no SDK retry, 45 s (chat, drafts) or 60 s (specialists, support) timeout. Structured outputs use `output_config.format` with the schema reduced to what Anthropic's strict mode accepts (length and numeric bounds are dropped; Orbit's zod validation of the answer still enforces them). The hosted web search is `web_search_20260209` with direct calls and `max_uses` from the specialist's remaining searches; its results and citations are reported as the same synthetic `web_search_call` items the runner already counts and prices (`webSearchMicrosPerCall`). Client-executed tool search stays OpenAI-only.

**Usage and cost.** Anthropic's `input_tokens` is the uncached remainder; Orbit's prompt size is `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`, settled with the rate card's cached-input and cache-write rates (defaults: the input rate and 1.25x input). Thinking tokens are part of `output_tokens`. A missing cache count settles all input at the highest rate (ADR 0003). HTTP 400, 401, 403, 404, 413, 422, 429 and 529 (overloaded) from Anthropic are not billed (`MODEL_REQUEST_NOT_ACCEPTED`, reservation settles at 0); everything else after transmission stays unknown. A safety refusal (`stop_reason: refusal`) is billed: drafts end with `MODEL_REFUSAL` (never retried), a chat turn with `CHAT_MODEL_CONTENT_FILTER`; a cut-off answer (`max_tokens`) is billed and, for drafts and specialists, fails the schema check as before.

**Provider budget (the Claude credit).** Per project, `providerBudgets.anthropic`: the credit per billing period (`monthlyMicros`, default 100 USD), two warning thresholds (`warnMicros` 75, `warn2Micros` 90), the internal stop (`stopMicros` 95) and the day the billing period starts (`anchorDay`, 1–28, UTC; the credit renews on the subscription date, not necessarily the 1st). `reserve` refuses a reservation of an Anthropic model that would pass the stop with `PROVIDER_BUDGET_STOP` (409); the check runs under the project lock, so parallel calls of one project are checked one after the other, and in-flight and unknown reservations count at their reserved amount. The spend is Orbit's own calculation from its reservations; the credit balance is a manually verified value (`credit.amountMicros`, `verifiedAt`), never synchronized with Anthropic: this account type has no credit API, and the Usage and Cost Admin API needs an organization admin key. The thresholds surface as the attention item `platform_provider_budget` (warning from 75 %, critical from 90 % and when stopped) and on Settings → AI. With several projects sharing one key the owner splits the credit across the projects' budgets.

**Fallback.** Off by default. With `fallback.onProviderBudgetStop: "openai"` saved by the owner, a call the Anthropic budget would stop before transmission is routed to the task class's OpenAI tier model instead (verified and priced, or the stop stands); the span is named `messages.create (fallback)` / `responses.stream (fallback)` and the reservation records the OpenAI model. A transmitted call is never retried on another provider.

**Not used.** Dynamic web-search filtering, the batch API, the 1-hour cache, task budgets, fast mode, images and embeddings on Anthropic.

Verify live with `scripts/anthropic-smoke.ts` (one Haiku call, at most 64 output tokens; needs `ANTHROPIC_API_KEY` in the shell, never in the repository).

## Finance extraction and file input (2026-10-23, local; flag off)

The finance module (`docs/FINANCE.md`, ADR 0012) adds the task class `finance_extraction` and the run kind `finance` (`AgentRun_kind_check` widened by the additive migration `202610230001_platform_finance_prerequisites`).

**Route.** Like every task class, `finance_extraction` resolves an explicit saved route first (Settings → AI, section "Finance extraction"; default ceiling 4,000 output tokens), otherwise the legacy `standard` tier. The provider catalogue suggests `claude-sonnet-5-5` for it; nothing is used until the owner verifies and prices the model and saves the route. A route that is unverified or unpriced fails closed as usual.

**File input.** `respond()` accepts user input parts `input_file` (PDF) and `input_image`. The OpenAI adapter passes them through; the Anthropic adapter maps them to `document` and `image` content blocks, and text-only messages map exactly as before. A model without the PDF or image capability is rejected **before** transmission (`AI_INPUT_UNSUPPORTED`). The pre-transmission estimate adds a conservative allowance of 3,000 input tokens per PDF page and 1,600 per image (`attachmentInputTokens` in `packages/ai/src/cost.ts`) on top of the instruction and text bytes; settlement uses the reported usage.

**Calls.** Each document is one call under the budget category `finance_document`: spend mandate (the active project policy), the finance daily ceiling (`aiDailyCeilingMicros`, default USD 2 per UTC day; settled plus open reservations), reservation, settlement. No tools, `store: false` on OpenAI, strict structured output validated again by zod and deterministic checks. A document over 10 MB or 20 PDF pages is not sent. An unknown outcome settles as unknown and is never retried automatically; a request the provider refuses is not billed. The run stops before the call if the AI configuration was saved meanwhile (`FINANCE_ROUTE_CHANGED`). No paid call was made during implementation.

## AI project manager task classes (2026-10-25, local; flag off)

The AI project manager (ADR 0017, `docs/WORK.md`) adds the task classes `pm_plan` (plans and coding briefs; default ceiling 12,000 output tokens, legacy `quality` tier) and `pm_analysis` (status reports and re-prioritization analyses; 3,000 output tokens, legacy `standard` tier), and the run kind `work_pm` (`AgentRun_kind_check` widened by the additive migration `202610250006_work_pm_run_kind`). The provider catalogue suggests `claude-sonnet-5-5` for plans and `claude-haiku-5-5` for analyses; as for every class, nothing is used until the owner verifies and prices the model and saves the route (Settings → AI, "Project manager plans" and "Project manager reports").

**Structured runs.** PM calls go through the platform helper `runStructured` (`apps/api/src/platform/agents/structured-run.ts`): R0 read tools only (a write tool or a tool the member may not use is refused before the run), optional hosted web search priced per search, a strict output schema, an input limit checked before any reservation (`AGENT_CONTEXT_LIMIT`), tool results cut at 12,000 characters. Each model call takes the spend mandate, the caller's own ceiling, a reservation under `<callKey>:<n>` and settlement; a repeated job attempt with the same call key finds the reservation and sends nothing (`outcome_unknown`). An invalid answer fails with `AGENT_OUTPUT_INVALID` after its cost is settled; an unclear call stays unknown and is never resent.
