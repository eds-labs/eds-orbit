# Matomo report ingestion

Status: local implementation and mocked-adapter/real-PostgreSQL verification passed. No existing Matomo instance, token, tracking configuration, or production metrics were contacted or changed.

`apps/api/src/modules/matomo.ts` exports `matomoImportInput`, `importMatomoReport`, `normalizeMatomoReport`, `importMatomoSnapshot`, and `matomoDayInterval`. The owner action accepts connector ID, approved site ID, explicit `YYYY-MM-DD` day, IANA site timezone, currency, one supported reporting method, and an optional goal ID for `Goals.get`. Supported imported methods are `VisitsSummary.get`, `Referrers.getCampaigns`, `Actions.getPageUrls`, and `Goals.get`. The existing connector enforces its five-method read allowlist, HTTPS, POST-body token authentication, bounded transport and a 1,000-row limit. Page URL reports request `flat=1` and do not recursively fetch pages or subtables.

The real external report call runs outside the project transaction. The importer checks the owner role, connector provider/read-verification status and site scope before the call, then rechecks connector version/status before storing. API errors and invalid report shapes do not create partial metrics. Secrets and raw provider bodies are not persisted in metrics or audit records.

Normalized rows retain connector/site/account/report method, source day, exact UTC interval, site timezone, currency, native metric fields, provider fetch timestamp and a stable content hash. Timezone and currency are explicitly marked operator supplied; this importer does not independently verify Matomo site settings. Day intervals follow the supplied website timezone, including 23- and 25-hour DST days. Matomo defines report periods in the website timezone and supports unformatted metrics for further processing. [Matomo Reporting API](https://developer.matomo.org/api-reference/api)

Missing values remain `null`; measured zero remains zero. Actions are not reinterpreted as clicks, visits converted are separate from conversion counts, and revenue is separate from spend. `Goals.get` additionally checks goal configuration; absent configured goals produce unavailable conversions/revenue rather than invented zeros. Page URL display labels remove query strings/fragments; private raw URL query values are neither stored nor logged.

Account dimensions include connector, site, report method and goal. Page reports additionally include page identity because visits to multiple pages are not disjoint sessions. Existing insight aggregation refuses mixed account dimensions, preventing a site summary from being added to its campaigns or page totals. Bounded-report completeness remains false; no global-total completeness or automatic winner is claimed. Labels and report membership are descriptive provider data, not publication or budget instructions.

An unchanged repeated row reuses its metric identity. A changed value invokes the existing correction lifecycle, preserves versions, and invalidates insights referencing the old metric. Missing rows in a later bounded report are not deleted, because a top-row snapshot cannot prove that earlier rows disappeared.

Verification: nine normalization/import tests plus one transport test passed. They cover DST, missing/zero values, provenance mismatch, URL privacy, duplicate/invalid rows, real-SQL dedup/correction/history, insight invalidation, owner/site/connector fences, absent goals and report denominator separation. Live report permissions, field shape on the target installation, site timezone/currency configuration and real data completeness remain connector acceptance work.
