# Matomo report ingestion

Orbit reads day reports for the Matomo website assigned to the project. The owner can import an individual day under **Marketing → Analytics** or enable scheduled imports on the same page.

`apps/api/src/modules/marketing/analytics/matomo.ts` exports `matomoImportInput`, `importMatomoReport`, `normalizeMatomoReport`, `importMatomoSnapshot`, and `matomoDayInterval`. The owner action accepts connector ID, approved site ID, explicit `YYYY-MM-DD` day, IANA site timezone, currency, one supported reporting method, and an optional goal ID for `Goals.get`. The allowed methods are `VisitsSummary.get`, `Referrers.getCampaigns`, `Actions.getPageUrls`, `Goals.get`, `Actions.get` and `SearchEngineKeywordsPerformance.getKeywordsGoogleWeb`. The connector enforces the reporting-method allowlist, HTTPS, POST-body token authentication, bounded transport and a 1,000-row limit. Page URL reports request `flat=1` and do not recursively fetch pages or subtables.

The real external report call runs outside the project transaction. The importer checks the owner role, connector provider/read-verification status and site scope before the call, then rechecks connector version/status before storing. API errors and invalid report shapes do not create partial metrics. Secrets and raw provider bodies are not persisted in metrics or audit records.

`Actions.get` imports page views and measured outbound link clicks as separate website counters. Google Web Search impressions and clicks require the Matomo Search Engine Keywords Performance feature and an authorized Google Search Console property for the site. Orbit only stores a combined row per day for the keyword rows Matomo returns. Empty results stay empty. Keyword labels are discarded before persistence. Search Console property totals can also include data outside the returned keyword rows. Ads and social metrics come from their respective platforms. [Matomo Search Console setup](https://matomo.org/faq/reports/import-google-search-keywords-in-matomo/)

Scheduled imports re-read today and yesterday twice daily for website reports and revisit the seven most recent closed dates for optional Google Web Search imports. Owners can select the additional reports when configuring their schedule. Owners can import older dates one day at a time.

The Matomo daily chart shows up to 30 days ending on the most recent date of the selected report, with an accessible table of daily values. It uses the project-scoped `GET /api/projects/:projectId/marketing/matomo-trend` endpoint, which returns the latest 500 aggregate rows across supported chart series and marks truncated results. Missing days are gaps and measured zero has its own mark.

Normalized rows retain connector/site/account/report method, source day, exact UTC interval, site timezone, currency, native metric fields, provider fetch timestamp and a stable content hash. Timezone and currency are explicitly marked operator supplied; this importer does not independently verify Matomo site settings. Day intervals follow the supplied website timezone, including 23- and 25-hour DST days. Matomo defines report periods in the website timezone and supports unformatted metrics for further processing. [Matomo Reporting API](https://developer.matomo.org/api-reference/api)

Missing values remain `null`; measured zero remains zero. Actions are not reinterpreted as clicks, visits converted are separate from conversion counts, and revenue is separate from spend. `Goals.get` additionally checks goal configuration; absent configured goals produce unavailable conversions/revenue rather than invented zeros. Page URL display labels remove query strings/fragments; private raw URL query values are neither stored nor logged.

Account dimensions include connector, site, report method and goal. Page reports additionally include page identity because visits to multiple pages are not disjoint sessions. Existing insight aggregation refuses mixed account dimensions, preventing a site summary from being added to its campaigns or page totals. Bounded-report completeness remains false; no global-total completeness or automatic winner is claimed. Labels and report membership are descriptive provider data, not publication or budget instructions.

An unchanged repeated row reuses its metric identity. A changed value invokes the existing correction lifecycle, preserves versions, and invalidates insights referencing the old metric. Missing rows in a later bounded report are not deleted, because a top-row snapshot cannot prove that earlier rows disappeared.

Local acceptance uses a mocked provider and isolated PostgreSQL. Check live report permissions, a closed-date response from the target installation, the site timezone/currency and Search Console coverage before relying on the provider totals.
