# Marketing Creative Studio

State (2026-10-27): implemented locally on branch `claude/orbit-creative-studio-v2-3ae0b3`, **not pushed, not deployed**, `ORBIT_CREATIVE_STUDIO` off. Design: [specs/2026-10-26-marketing-creative-studio-design.md](superpowers/specs/2026-10-26-marketing-creative-studio-design.md); plan: [plans/2026-10-26-marketing-creative-studio.md](superpowers/plans/2026-10-26-marketing-creative-studio.md); routes: [API_CONTRACT.md](API_CONTRACT.md#creative-studio); model route: [MODEL_ROUTING.md](MODEL_ROUTING.md#creative-vision-review-2026-10-27-local-flag-off).

The Studio turns a social post into a finished creative: AI artwork and/or approved product screenshots, headline, subline, optional call to action and the unchanged approved logo, composed per channel format and checked deterministically before a person sees it. It is generic: a project describes its brand and templates as data in the marketing profile; nothing in the code names a product, logo or colour of a real brand.

## Flag, scope and rollback

- `ORBIT_CREATIVE_STUDIO` (default `false`; `.env.example`, `docker-compose.yml`, `packages/config`). Getters read it per call. With it off there is no creative route (404 `NOT_FOUND`), no assistant tool, no UI, the strategy and copywriting prompts and schemas are the old ones, and every existing path behaves as before (CS-D6). No migration: brand kit data lives in the profile JSON, creatives are `creatives` entities, renditions are assets.
- The Marketing module must be active for the project (`MODULE_DISABLED` otherwise, see [MODULE_ACTIVATION.md](MODULE_ACTIVATION.md)). A project opts in by its brand kit (a primary logo is required) and, for automation, by the assignment field `creative`.
- Rollback: set the flag to `false` and redeploy, or redeploy the previous image. Stored creatives and renditions are ignored by old code; posts that already carry a rendition keep it as a normal approved PNG.
- Rollout note: compose changes alter rendered bytes. Creatives stored before a deploy that changed the engine recompose differently (layout, scrim, logo size); the stored renditions stay as they are until someone recomposes. The legacy uLiquid `brand_landscape` banner (assignment `banner`) is unchanged byte for byte (CS-D3).

## Brand kit

Settings → Brand (owner edits, others read). All fields are optional in `visualIdentity` of the marketing profile, so every saved profile stays valid; saving makes a profile version and invalidates pending content as it does today.

| Field | Meaning |
| --- | --- |
| `logoAssetId`, `logos.{secondary,onDark,onLight,mark}` | Approved raster logos. The composer picks the variant by the luminance behind the anchor. A logo is placed with its exact approved bytes (SHA-256), never recoloured, cropped or redrawn. |
| `productAssetIds` (≤ 20) | Approved `screenshot` / `product` assets used unchanged (scaled, aspect kept). |
| `imagery` | `kind` (photo, illustration, 3d, flat, mixed), `mood` (≤ 300), `subjects` (≤ 500), `avoid` (≤ 20 × 200): art direction input. A partial update over MCP replaces `imagery` as a whole. |
| `typography` | `headingWeight` 600/700/800, `headingCase` none/upper. Fonts are the installed Inter and DejaVu Sans only (no new font dependency). |
| `forbiddenDesigns` (≤ 20 × 300) | Layout or design variants the art direction must avoid. |
| `creative.templates` | Per template `{enabled, variant?}`. An explicit manual template ignores `enabled` (R30); automation respects it. |
| `creative.formatsByChannel` | Provider identifier → formats (override of the channel mapping). |
| `creative.logoPlacement` | `auto` (first free corner) or a corner. |
| `creative.ctaStyle` | `pill`, `outline`, `none`. |
| `creative.maxArtCorrections` | 0, 1 (default) or 2 paid art attempts per creative. |
| `creative.visualReview` | Optional vision review (default off). |

The Brand tab lists stale references (an unapproved or outdated logo, screenshot or product) with a Remove button; a stale reference blocks every profile save otherwise. The `creative` block is read-only over MCP.

**Assets and rights.** Brand assets stay `assets` entities. Upload and Drive import accept the types `screenshot` and `product` (the web upload form offers them, R61). The owner-set flag `providerUse` (default `false`) allows an asset to be sent to an AI provider. Every asset type sent to any provider (style references, vision review) must be approved, usage-approved and `providerUse` (R28, one shared helper `mayTransmitToProvider`). Art generated by Orbit for an assignment run is stored with `providerUse: true` (R59): it already came from the provider; logos and screenshots still need the owner's flag. A rendition counts as an approved image only while every component in its `rightsSource` is still approved with the recorded SHA-256 (R36); the owner-confirmed Postiz draft handoff checks the same (R48).

## Templates, variants and formats

Seven templates, each with 2–3 variants (the first is the default). Side variants exist only on `landscape` and `square`; when a project default does not exist for a format the resolver uses the first valid one (R1), and on landscape it prefers the first side variant of a template with a product or lifestyle (R12, R16). A manual explicit variant a format does not offer fails with `CREATIVE_VARIANT_NOT_AVAILABLE` (R31).

| Template | Variants | Art | Product |
| --- | --- | --- | --- |
| `product_showcase` | product_right, product_left, text_top | optional | required |
| `feature_highlight` | text_top, product_left, product_right | optional | required |
| `problem_solution` | text_top, text_bottom | required | optional |
| `lifestyle` | text_bottom, text_top, text_side | required | none |
| `tips` | text_top, centered | optional | none |
| `announcement` | centered, text_bottom | optional | optional |
| `brand_message` | centered, text_bottom | required | none |

Copy limits (characters): eyebrow 32, CTA 24, headline 60 (tips and brand_message 70), subline 120 (tips 180). Text is set with Pango through sharp, so measured size equals drawn size; it auto-fits between a template's maximum and minimum and fails with `TEXT_OVERFLOW` rather than being cut.

| Format | Size | Default channels |
| --- | --- | --- |
| `feed_portrait` | 1080 × 1350 | instagram, facebook |
| `square` | 1080 × 1080 | unknown channels |
| `story` | 1080 × 1920 (top 250 / bottom 340 px reserved) | override only |
| `landscape` | 1200 × 630 | x, linkedin, telegram |
| `wide` | 1600 × 900 | legacy `brand_landscape` only |

One rendition is composed per format a post needs (`creative.formatsByChannel` overrides the defaults); a post carries the rendition for its channel's format. Art is generated once per brief from the primary format's layout (R32); other formats crop the same art.

## Channel rules

Instagram (`instagram`, `instagram-standalone`): caption 2,200 UTF-16 units, media required (preflight `MEDIA_REQUIRED`; a text-only draft can still be reviewed; the agent review leaves it for the owner), Postiz `post_type: "post"` (stories are not modelled). Facebook: 50,000 (the Postiz client's bound; Postiz itself allows 63,206), media optional. Both carry `liveCapabilityKnown: true`, verified read-only against the Postiz integration schema. Preflight keeps requiring an approved PNG. Instagram captions have no clickable links.

## Quality assurance

Deterministic checks (`creative/quality.ts`, thresholds in `CREATIVE_THRESHOLDS`, calibrated on the demo fixtures and listed in spec §9):

| Code | Threshold / rule | Handling |
| --- | --- | --- |
| `CREATIVE_DIMENSIONS`, `SAFE_AREA_VIOLATION`, `LAYER_OVERLAP` | exact format size, layers inside safe area, no overlap | render bug → `needs_owner` |
| `CREATIVE_FILE_TOO_LARGE` | PNG > 8 MiB | re-encode once, else `needs_owner` |
| `TEXT_OVERFLOW` | copy does not fit at minimum size | other variant, then one copy revision |
| `TEXT_CONTRAST_LOW` | < 4.5:1 body text and every subline; < 3:1 large text (≥ 32 px) | stronger scrim, then other variant |
| `TEXT_BACKDROP_BUSY` | busyness behind text > 0.015 (R17) | stronger scrim (under a full tint capped at 0.6, R23/R23a), then variant (R22) |
| `LOGO_CONTRAST_LOW` | < 2:1 | other logo variant, then plate |
| `LOGO_INTEGRITY` | bytes ≠ approved SHA-256, aspect changed, drawn longer side < 0.06 of the canvas's shorter side (R19) | **refuse** |
| `SCREENSHOT_INTEGRITY` | bytes ≠ approved SHA-256 or aspect changed | **refuse** |
| `ASSET_RIGHTS` | component not approved, use not covered, outdated, other project | **refuse** |
| `SUBJECT_TOO_SMALL` | all connected subjects ≥ 64 cells cover < 25 % of the drawn art | art correction |
| `EMPTY_AREA_EXCESSIVE` | flat cells outside the reserved zones > 45 % of the drawn art | art correction |
| `ASSET_UPSCALED` | a raster layer drawn at > 1.5× its source | warning only |

Art checks judge the art as it is drawn (`drawnArt`, `artZones`, R21) on an area-averaged 64-cell grid, so grain, JPEG artefacts and resolution do not change a verdict (R20, R25, R26). A decorative strip beyond 4:1 is not judged (R24); art in a band beyond 2.5:1, such as the tips band on square and portrait (2.9:1), is judged for `SUBJECT_TOO_SMALL` only and `EMPTY_AREA_EXCESSIVE` is a warning there (R60). Known limits (R27): a smooth gradient or vignette can count as subject; `drawnArt` composites onto black, which matters only for art with an alpha channel.

**Refusals (R34, R46).** `LOGO_INTEGRITY` (every reason), `SCREENSHOT_INTEGRITY` and `ASSET_RIGHTS` are never overridable by `acceptQaFindings`: produce or recompose stores nothing and answers 409 with the code and a `detail` of ids and codes (R56). `needs_owner` findings can be accepted only by an owner.

## Corrections and limits

1. **Free and deterministic:** other layout variant (up to 2), stronger scrim, other logo variant or plate, smaller text scale. Recomposition (variant, logo placement, text scale, edited copy) is free and keeps the art.
2. **Art regeneration** (owner, costs one image): at most `maxArtCorrections` (default 1, maximum 2) per creative, with a targeted prompt delta (`subject_larger`, `calm_text_zone`, `more_detail`). Every attempt that was sent counts (`ART_CORRECTION_LIMIT` before anything is reserved). Regenerate replaces the art with new Orbit art, also uploaded art (R52).
3. **Still failing:** the creative is `needs_owner`; the content gets `CREATIVE_QA_FAILED` and is left for the owner. Nothing is attached as approved and nothing is published.

Before new art is paid for (produce with `generateArt`, regenerate) one free placeholder composition runs and refuses art-independent failures (`TEXT_OVERFLOW`, `LOGO_INTEGRITY`, `SCREENSHOT_INTEGRITY`, `ASSET_RIGHTS`) so no money is spent on a creative that cannot succeed (R53). New art is stored unapproved: the creative is `needs_rights` until the owner approves the art and recomposes. After a failure that followed payment, the error `detail.artAssetId` names the paid art, which stays as an unapproved reference. The client `requestId` (uuid) makes a retried paid request answer `RESERVATION_ALREADY_USED` instead of paying twice (R51).

## Costs and the vision review

- Composition, recomposition and deterministic QA are free. Only art generation and the vision review cost money, and both go through the existing path: spend mandate, reservation before transmission, settle after the call, unknown outcomes stay counted and are never resent. There is no automatic budget increase; run, package, project and organisation limits apply. Manual paid requests are limited to 3 a minute per client and need `confirmMaximumCostMicros` and `confirmPromptMayBeSentToProvider`.
- **Vision review (CS-D2).** Optional per project (`creative.visualReview`, default off), owner-started (`POST …/review`). Task class `creative_review`, `respond()` with the first format's rendition as `input_image`, a strict rubric of seven scores from 1 to 5 (subject, balance, legibility, brandFit, messageFit, channelFit, value) and issues of kind art, layout, copy or logo. Orbit computes the verdict: `pass` when every score ≥ 3 and the mean ≥ 3.5, otherwise `needs_correction`. It runs only when every component has `providerUse` (`PROVIDER_USE_REQUIRED`). The review is keyed on the rendition's SHA-256 (`creative-review:<creativeId>:<sha>`): an already judged rendition returns its stored verdict without a second payment (R50). It is scoped per creative; a newly produced creative starts without a verdict (R57, known limit: no per-rendition verdict history, so recomposing back to an earlier layout or re-reviewing identical pixels after an unknown outcome needs a visible change). A failing verdict sets `qa.verdict: "needs_owner"`, survives recomposition (R49) and, on an attached creative, keeps the status `attached` (R5a). It never approves, attaches or publishes anything. The run kind is `image` (telemetry), see MODEL_ROUTING.md.
- The assignment card shows the templates and an image cost estimate; the consent text names the logo and product assets used.

## Creative statuses

`status` is the lifecycle: `composed`, `needs_owner`, `needs_rights`, `attached`, `superseded`. `qa.verdict` is the quality: `pass`, `corrected`, `needs_owner`. Attaching sets `attached`; recomposing an attached creative makes new renditions while the post keeps the attached one until the next attach (R5). Attaching resets the content to `draft` and re-runs `reviewContent`, like `attachPackageImage`; repeating an attach changes nothing.

## Assignments and packages

- **Assignment field `creative`** (social only, `image: true`, exclusive with `banner`): `{templates?: TemplateId[1..7], artPer: "run" | "post" (default post), imageKind?: "auto" | "scene" | "product" | "graphic" (default auto)}`. Hashed into the confirmation only when set, so existing confirmations stay valid. Readiness 409 codes in order: `CREATIVE_STUDIO_DISABLED`, `CREATIVE_SOCIAL_ONLY`, `CREATIVE_NEEDS_IMAGE`, `CREATIVE_AND_BANNER`, `CREATIVE_LOGO_REQUIRED`; checked at proposal, change, confirmation, resume and in the visual step before any cost.
- The strategy specialist returns a structured `creative` brief (goal, audience, keyMessage, imageKind, motif ≤ 400, setting, template, mood); the copywriter returns `coreMessage`, `hook` and `creative` copy (`CREATIVE_TEXT_TOO_LONG` is a revisable code, `CREATIVE_TEXT_MISSING` for absent copy; creative copy is never in the claims ledger). The visual step generates one art per run or per post, checks it and applies bounded art corrections within the run budget. Composition runs per slot and channel format after the drafts exist. In a run, a creative with findings stays `attached` with `qa.verdict: "needs_owner"`; the agent review reports `CREATIVE_QA_FAILED` from `qa.verdict`, not from the status.
- **CS-D7: agent review authority does not cover creatives.** With `delivery: "publish"` such posts wait for the owner's release until the review eval set has creative cases and has passed; `postiz_draft` is unchanged. A channel that cannot carry the image holds back only that channel (`CREATIVE_MEDIA_REFUSED`).
- **Content packages.** With the flag on and a primary logo, attaching a package image composes renditions per channel draft instead of attaching the raw image. A QA failure fails the whole attach atomically (409 `CREATIVE_QA_FAILED` with the failing content ids and codes); an owner may pass `acceptQaFindings` (R54). The snapshot exposes `carriesPackageImage` per draft (R58), the web hides "Attach package image" then.

## Known limits and follow-ups

- Task 22 (live acceptance, one real image per demo brand, at most 1 USD) is not run: it needs Mario's go-ahead and key.
- **CS-D3 follow-up:** uLiquid still uses the hard-coded `brand_landscape` banner. Moving it to a generic template through its profile, then removing the hard-coded template, is a later step.
- Fonts are Inter and DejaVu only; more fonts need font packages in the image (new dependency).
- No video, carousels or animated formats; no new image providers (adapter-ready, needs a decision).
- Marketing assets stay base64 `Entity` data, not platform files.
- Instagram stories are not modelled; links in Instagram captions are not clickable (a "link in bio" copy rule is later).
- Review eval cases for creatives are missing, so agent authority does not cover them (CS-D7).
- Vision verdict is per creative, with no per-rendition history (R57).
- Art direction: a smooth gradient can pass `SUBJECT_TOO_SMALL` (R27); product prompts ask 60–75 % subject size while two reserved zones exist; busyness is inflated by synthetic grain in fixtures.
- Non-default stacked landscape variants (for example product_showcase `text_top`) offer less text room and may need a variant switch.
