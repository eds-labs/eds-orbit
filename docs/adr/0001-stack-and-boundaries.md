# ADR 0001: Self-hosted modular monorepo

Accepted for isolated implementation, 2026-09-17. One web-next-custom-postgres preset, with explicit self-hosted PostgreSQL adaptation. Next App Router never reads the product DB. Fastify owns validation, auth and authorization; Prisma 7 with pg driver adapter manages normal relations. PostgreSQL SQL migration installs pgvector, FTS triggers, composite tenant foreign keys, FORCE RLS and separate nonprivileged roles. Exact vector search is baseline; no ANN until measured need. BullMQ carries IDs; PostgreSQL outbox and action journal determine business state.

Alternative web-next-supabase would provide hosted auth/storage convenience but introduces a second platform lifecycle beyond the requested independent server stack. Better Auth keeps sessions and password cryptography in a maintained library; no custom password algorithm. Generic Entity envelopes keep typed JSON business payloads versioned; normalized relational knowledge tables enforce source/version/chunk scope. This trades SQL visibility into business JSON for less duplicated domain infrastructure. Every mutation must validate its specific schema; generic writes are restricted.

Risks: RLS context bugs, provider ambiguity, stale evidence, prompt injection, permission changes during work, cost and quota races. Tests use actual app role, repeated pool connections, concurrent reservations, deletion fences and guarded publication. Local rollback stops only Orbit processes and retains separate volumes; production adoption is a separate approved change.

Verified sources: https://better-auth.com/docs/adapters/prisma (Prisma7 driver adapter); https://fastify.dev/docs/latest/Reference/LTS/ (Fastify5 LTS); https://github.com/pgvector/pgvector (0.8.6; exact search); https://nextjs.org/docs/app/getting-started/installation (Node minimum). Registry exact versions recorded in lockfile. `prisma` latest tag was a prerelease; selected stable CLI7.10.0 to match client/adapter7.10.0 instead.
