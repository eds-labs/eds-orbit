# Ads A0 — Meta Verification Spike (setup guide and checklist)

> **For agentic workers:** step A0 of the programme plan [`2026-11-07-ads-module.md`](2026-11-07-ads-module.md). The decision half of A0 is done (ADR 0025). This document covers the spike: Mario sets up the Meta side, Claude runs the agreed calls, both record the results below. No Orbit code is written in A0; nothing is merged except this document and its results.

**Goal:** Confirm or correct every Meta fact in plan §2.6 that A1–A8 rely on, record sanitized response examples for the fake Graph server (A2), settle A-D1 (module id) with an ad-blocker test, and do all of it without spending money or touching production.

**Time box:** about half a day of Mario's setup time plus one Claude session.

**Baseline:** `main` at `6b021186`; Marketing API version **v27.0** (re-checked at A2 start).

---

## 1. Rules for the spike

- **No spend.** Writes go only to the Meta **sandbox ad account** (ads never run, no payment method) and, optionally, to a real test ad account **without a payment method**. No call ever touches an ad account that has a payment method, except the read calls in §4.2 if Mario approves them.
- **No production.** Nothing in Orbit production changes: no flag, no migration, no connection, no deployment.
- **Secrets stay in the macOS keychain.** Tokens and the app secret are entered with `read -s` (the `security` prompt cuts values above 128 characters), never typed into chat, a repository file, a URL or shell history. Requests send tokens in the `Authorization` header, not as `access_token` query parameters.
- **Raw responses stay outside the repository** (`~/orbit-ads-spike/`). Only sanitized fixtures (ids replaced, names and texts neutral, no tokens, no personal data) move into the repository, and only in A2 after review.
- **Each call group needs Mario's go** (§3). A go covers only the group it names.
- **Clean-up is part of the spike** (§6).

## 2. Mario's setup (Meta side)

Meta's dashboard labels change often; the labels below are from Meta's documentation on 2026-11-07. Record anything that looks different in §7.

### 2.1 Business portfolio

1. Open Business Settings (business.facebook.com/settings) for the portfolio the app should belong to (EDS Labs).
2. Note in §7 whether the portfolio is **verified** (Security Center). The spike does not need it, but Meta states that ads can run only once the connected portfolio is verified, and Advanced Access needs Business Verification (A-D17).

### 2.2 A new Meta app for Ads (A-D2: not the Social app)

1. developers.facebook.com/apps/creation/ → **App details:** name `Orbit Ads`, contact e-mail → **Next**.
2. **Use cases:** select **Create & manage ads with Marketing API** (nothing else) → **Next**.
3. **Business:** choose the EDS Labs portfolio → **Next**.
4. **Requirements:** read and note what Meta lists (App Review items) → **Next** → **Go to dashboard**.
5. Leave the app unpublished (development mode). Do not request App Review now.
6. **Use cases → Customize:** check that the required items are present: Ads Management Standard Access, `ads_management`, `ads_read`, `business_management`, `pages_read_engagement`, `pages_show_list`, `public_profile`. Do **not** add optional permissions yet (`pages_manage_ads` only if Q1 shows it is needed).
7. **App settings → Basic:** note the App ID; reveal the App secret and store it (§2.5). If an **Advanced** setting "Require app secret" exists, switch it on (every server call then needs `appsecret_proof`; Q13 checks it).
8. **Settings:** note the shown **Ads API access level** in §7 (expected: Limited / Standard Access).

### 2.3 Sandbox ad account and spike token

1. **Quickstart → Create an Ad Campaign** → choose a language → **Create Sandbox Ad Account**; tick one Facebook Page of the portfolio → **Create**. Note the sandbox account id (`act_…`) in §7.
2. **Generate Access Token:** select `ads_management`, `ads_read`, `business_management`, `pages_show_list`, `pages_read_engagement` → **Get Token**. Meta says this token is valid for about two months. Store it at once (§2.5); it is revoked in §6.

### 2.4 Facebook Login for Business configurations (for Q2, Q14)

1. **Facebook Login for Business → Configurations → + Create configuration.**
2. Configuration A, name `Orbit Ads – user token`: access token type **User access token**, the longest offered expiration, assets **ad accounts** and **Pages** (Instagram accounts if offered), permissions as in §2.3 → **Create** → note the Configuration ID.
3. Configuration B, name `Orbit Ads – system user`: access token type **System-user access token**. Meta documents this type for tech providers only: record whether the dashboard allows it, and its expiration options. If it is refused, note the message and skip B.
4. **Facebook Login for Business → Settings → Valid OAuth Redirect URIs:** add `http://localhost:4310/api/ads/oauth/callback/meta` (Orbit's local web port). Record whether Meta accepts a `localhost` redirect for an unpublished app.

## 4. Calls Claude runs (after the matching go)

Base `https://graph.facebook.com/v27.0`. Each call saves the response body and the response headers under `~/orbit-ads-spike/<group>/<name>.{json,headers}`.

### 4.0 Shell setup (per session)

```bash
TOKEN=$(security find-generic-password -s orbit-ads-spike-meta-token -w)
APP_SECRET=$(security find-generic-password -s orbit-ads-spike-meta-app-secret -w)
PROOF=$(printf %s "$TOKEN" | openssl dgst -sha256 -hmac "$APP_SECRET" -r | cut -d' ' -f1)
G=https://graph.facebook.com/v27.0
get() { curl -sS -D "$2.headers" -o "$2.json" -H "Authorization: Bearer $TOKEN" "$G$1&appsecret_proof=$PROOF"; }
```

`get '/me?fields=id,name' ~/orbit-ads-spike/g2/r1` is the pattern for reads; writes use `curl -X POST` with `-F` form fields and the same header and proof. `APP_ID`, `SANDBOX` (`act_…`) and `PAGE_ID` are set from §7.

### 4.7 Login flow (G6, Mario in the browser and his own terminal)

1. Mario opens `https://www.facebook.com/v27.0/dialog/oauth?client_id=<APP_ID>&redirect_uri=http%3A%2F%2Flocalhost%3A4310%2Fapi%2Fads%2Foauth%2Fcallback%2Fmeta&state=spike&config_id=<CONFIG_A>&response_type=code&override_default_response_type=true` and grants the sandbox account and a Page. Nothing listens on port 4310; the browser shows an error page whose address contains `code=…`.
2. Mario exchanges the code in his terminal (the code is single use and expires within minutes; paste it at the silent prompt). First set the app id in the same terminal, for example `APP_ID=1234567890`. The command prints the answer without the token and stores the token in the keychain entry `orbit-ads-spike-meta-flfb-a`:

```bash
read -s CODE && curl -sS -G https://graph.facebook.com/v27.0/oauth/access_token \
  --data-urlencode client_id="$APP_ID" \
  --data-urlencode client_secret="$(security find-generic-password -s orbit-ads-spike-meta-app-secret -w)" \
  --data-urlencode redirect_uri=http://localhost:4310/api/ads/oauth/callback/meta \
  --data-urlencode code="$CODE" \
| python3 -c 'import json,os,subprocess,sys; t=json.load(sys.stdin); tok=t.pop("access_token",None); print(t); tok and subprocess.run(["security","add-generic-password","-U","-a",os.environ["USER"],"-s","orbit-ads-spike-meta-flfb-a","-w",tok],check=True)'; unset CODE
```
3. Claude runs R2 on that token (type, expiry, scopes) and R3 (which ad accounts the configuration granted).
4. Same for configuration B if §2.4 allowed it.
