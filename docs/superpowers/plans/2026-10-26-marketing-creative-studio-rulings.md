# Marketing Creative Studio — implementation rulings

Decisions the controller made while executing [the plan](2026-10-26-marketing-creative-studio.md) subagent-driven (2026-10-26/27). Each states the decision, the reason and the cost if it was wrong. Rulings override the plan's task text where they apply.

- **R1:** When a project's default variant is not in `variantsFor(template, format)`, the resolver (T8 resolveCreativeBrief, T9 pipeline) silently uses the template's first variant valid for that format; the schema stays as planned. — The spec wants templates configurable without code; format restrictions are engine facts. — If wrong: an owner's chosen variant is ignored on portrait formats (visible in the panel, easy to change).
- **R2:** compose colours text so it meets the QA requirement of its own size: eyebrow uses the accent only when contrast ≥ 4.5 (fontSize < 32) or ≥ 3 (≥ 32), else the body text colour; for a pill CTA the recorded backdrop is the pill colour, and when no label colour reaches the requirement the CTA falls back to outline style over the scrim (record `ctaStyleApplied`). — Keeps T4 output passing T5 checks by construction. — If wrong: some brands get an outline CTA instead of a pill.
- **R3:** An explicit logo corner that would intersect the text box shrinks the text box away from the logo band; layouts never overlap. The T3 loop test covers auto, the explicit-corner test also asserts no intersection. — Spec §6 forbids overlaps. — If wrong: less text room with some corners (TEXT_OVERFLOW earlier).
- **R4:** The creative status union from T8 on is `"composed" | "needs_owner" | "needs_rights" | "attached" | "superseded"`. — T10 needs needs_rights; defining it once avoids a type change later. — If wrong: nothing, a status is unused.
- **R5:** attachCreative sets the creative's status to "attached"; recomposing an attached creative creates new renditions with status composed/needs_owner while the content keeps the attached rendition until the next attach. — Spec §8 lists "attached". — If wrong: status display only.
- **R5a:** a failing vision verdict on an already attached creative sets qa.verdict needs_owner and keeps status "attached" (R5, attach idempotency, T14 reads qa.verdict). — Status = lifecycle, qa.verdict = quality. — If wrong: UI must show qa.verdict for attached creatives (T17).
- **R6:** T9 exports one composition core, `composeRenditions(...)` (compose per format + free corrections + art checks, outside transactions), used by produceCreative, recomposeCreative, composeRunCreatives (T14) and packages (T15). — DRY; the rubric treats duplicated logic as Important. — If wrong: an extra indirection.
- **R7:** T14 integration tests use x/telegram/linkedin channels (landscape) and an unknown channel (square); Instagram arrives in T16. — Avoids cross-task dependency. — If wrong: Instagram format path is covered only by T16 and T20.
- **R8:** T19's implementer starts the local stack (web 4310, api 4311, worker) with ORBIT_CREATIVE_STUDIO=true per README; if the stack cannot be started in this environment, the spec is still written and the task reports DONE_WITH_CONCERNS with the reason, and the browser run moves to T21 verification. — Environment, not code. — If wrong: the browser flow stays unverified until T21.
- **R9:** Task 3 dispatched while Task 2's review runs (Mario asked to proceed; templates.ts is independent of text.ts). Any Task 2 fix round waits until Task 3's implementer has finished; review packages then use explicit commit ranges. — Keeps one writer at a time. — If wrong: a Task 2 fix lands after Task 3, a small reordering of history.
- **R10:** fitText (a) rounds maxSize down / minSize up and tries integer sizes only; (b) measures the font's natural line pitch per font/weight/size from reference renders and sets Pango spacing = max(0, round(size*lineHeight - pitch)) (negative if sharp accepts it); (c) counts lines from the measured height (height − first-line height)/pitch + 1 and accepts when lines <= maxLines and height <= box.height (no size-proportional ink cap); (d) font must be a BrandFont (INVALID_BRAND_FONT) and weight one of 400/600/700/800, lineHeight/maxLines finite (INVALID_TEMPLATE_INPUT), so bad data never reaches Pango as raw markup. — The brief's formulas are an approximation; the spec (§6) binds "measured size = drawn size" and "never cut". — If wrong: slightly different shrink decisions; still never cut.
- **R11:** Inter is not installed on this Mac (fallback font); production has fonts-inter/fonts-dejavu-core. Unit tests assert relations only. T21 verification adds one run of packages/creative tests inside a Linux container with fonts-inter + fonts-dejavu-core (node:24 image) to confirm metrics. — Font availability differs per host. — If wrong: production text sizes differ from local renders (layout still never cuts).
- **R12:** When no variant is chosen explicitly, the resolver (T8 resolveCreativeBrief / T9) prefers, on landscape, the template's first side variant (product_right/product_left/text_side) for templates with a product box, because stacked variants leave too little text room on 1200×630; otherwise the template's first valid variant. — Task 3 measured 270–330 px offered vs ~341 px needed. — If wrong: a different default composition on landscape only.
- **R13:** compose anchors the text stack at the scrim's solid edge (top for "down", bottom for "up", middle for centred/full), and leaves the scrim at opacity 0 when a template has no art (brand fill backgrounds) unless contrast requires it; LayoutOptions.logoRole (added in T3) is passed through by compose. — Task 3 handoff notes. — If wrong: visual placement only.
- **R14:** On landscape, the text region of every template's default variant (after R12) must offer at least 342 px height (four text layers at minimum size, measured by Task 3); problem_solution's landscape regions are enlarged in Task 3's fix round. — Prevents TEXT_OVERFLOW on X/LinkedIn/Telegram for full copy. — If wrong: less art area on landscape problem_solution.
- **R15:** reservedZones are ordered [text, logo, product?]; when no product is attached the resolver/pipeline drops the product zone before art direction and EMPTY_AREA_EXCESSIVE. — Task 3 review minor 2. — If wrong: an empty product region counted as reserved.
- **R16:** R12 extends to lifestyle: on landscape the resolver prefers text_side (Task 4 found text_bottom text-dominated on 1200×630). — Visual quality. — If wrong: other landscape default for lifestyle.
- **R17:** text over busy art: compose also records backdrop busyness (mean detail energy under each text box, via Task 5's detail measure) and raises the scrim until busyness is below a threshold; QA adds TEXT_BACKDROP_BUSY (blocker, free correction = scrim). Task 5 owns both the measure and the compose hook. — Controller saw dark headline over busy mid-tone art (kestrel product_showcase landscape, scrim 0.15): legible but restless. — If wrong: slightly darker/lighter scrims on busy art.
- **R18:** logo box on landscape is too small (0.06·H = 38 px; wordmarks become tiny); T20 raises the logo box to height max(0.06·H, 0.075·W·(H/W ratio adj.)) — concretely height max(0.06·H, 48 px) and width up to 0.2·W for wordmarks — updating Task 3 tests accordingly. — Controller visual check. — If wrong: logos larger on landscape only.
- **R19:** logo box height = max(0.06·H, 0.05·W) (landscape 60 px; portrait/square/story unchanged), width stays 0.14·W (mark 0.10·W); plate padding = round(0.12·anchor height) instead of a fixed 14 px; LOGO_INTEGRITY minimum size = the drawn logo's longer side ≥ 0.06·min(W,H) (landscape 37.8 px, portrait/square 64.8 px, story 64.8 px). Task 3/4 tests updated accordingly. — A landscape creative with a square logo must not be an unfixable blocker; spec §9 only says "below minimum size", the plan's 0.06·W was a guess. — If wrong: logos slightly larger on landscape, minimum rule more lenient on landscape.
- **R20:** subject/flat detection moves to a grain-insensitive, resolution-independent measure: analyse the art downsampled by area-averaging to a fixed grid (≈64 cells on the short side, after a light blur); background colour = median of the border cells; a cell belongs to the subject when its colour differs from the background beyond a threshold OR its local (3×3 neighbourhood) luminance range is high; subjectCoverage = bounding-box area of the subject mask (largest connected component, small specks ignored) / total; flatShare = cells with low local range outside reserved zones. Text busyness (R17) is measured on a blurred, fixed-scale (e.g. 1/4) grey of the backdrop region (local deviation), so art resolution and JPEG do not swing the scrim. Thresholds recalibrated with the calibration test + spec §9; the analysis scale constant moves into CREATIVE_THRESHOLDS. New tests: the same good art as JPEG q70, a native 2048 render and with sigma≈2 noise give the same verdicts and a scrim within 0.1; a grain-free vector subject passes; flat art with noise fails; tiny subject on noise fails. — A false art blocker triggers paid regeneration; the measure must judge the motif, not texture. — If wrong: different but documented calibration; still deterministic.
- **R21:** art checks always run on the art as it will be drawn. compose's art-fitting step is exported as `drawnArt(art: RasterSource, layout: LayoutSpec): Promise<Buffer>` (the exact cover/contain fit compose uses, shared code) and `artZones(layout: LayoutSpec): RelBox[]` (canvas reservedZones intersected with layout.art, as fractions of the art box). `checkArt(png, reserved)` documents that both are in the drawn-art frame; tests and calibration use drawnArt + artZones, including sub-region templates (feature_highlight, tips, side variants). — Consistent QA for every template. — If wrong: one extra resize per check.
- **R22:** failedBlockers may contain "ASSET_RIGHTS"; planCorrection takes Array<CreativeCheck["code"] | "TEXT_OVERFLOW">, never corrects ASSET_RIGHTS (refusal), and sends TEXT_CONTRAST_LOW and TEXT_BACKDROP_BUSY straight to a variant correction (compose already drives the scrim to the layout max; "scrim" boost only when scrimOpacity < layout max). — Task 5 review minor 1. — If wrong: one wasted free recomposition.
- **R23:** the busyness-driven scrim increase (R17) is capped at 0.6 opacity for "full"/centred scrims (contrast-driven increases may still reach the layout max); when the backdrop stays busy at that cap, compose leaves it and QA reports TEXT_BACKDROP_BUSY, whose correction is a variant switch (R22). — A statement template must keep its motif visible; switching to text_bottom is the professional fix. — If wrong: more variant switches on busy art.
- **R23a:** R23's cap applies to "full" tints only; announcement/centered keeps its designed strong gradient scrim (text-dominant announcement template; capping made both brands' default announcement a blocker). — Ruling intent was to keep statement motifs visible; announcement is designed as a text-first layout. — If wrong: announcement motifs may be darkened on busy art (T20 visual pass checks).
- **R24:** checkArt treats a drawn art box with aspect > 4:1 or < 1:4 as a decorative strip: both art checks pass with detail {skipped: "ART_STRIP"} (no blocker, no regeneration). — Art in a 9:1 strip cannot be judged as a motif; regenerating cannot fix it. — If wrong: a weak strip goes unflagged (decorative only).
- **R25:** flatShare's denominator is all drawn-art cells (documented in spec §9), not "non-reserved cells" as the brief said; EMPTY_AREA_EXCESSIVE then cannot fire when > 55 % of the drawn art is reserved, SUBJECT_TOO_SMALL still catches flat art. — Re-review measured it as stable and the brief's denominator made reserved-heavy layouts noisy. — If wrong: an empty art region behind large reserved zones goes unflagged.
- **R26:** subjectCoverage = bounding box of all significant subject components (each ≥ a minimum cell count), not only the largest one, so two separate subjects are not read as one small subject (the largest-only rule produced a false SUBJECT_TOO_SMALL → paid regeneration). Applied in Task 5's fix round 2 with a test (two 400 px discs at opposite corners pass; tiny subject still fails). — False blockers cost money. — If wrong: scattered specks could count as a large subject (mitigated by the minimum component size).
- **R27:** smooth gradients/vignettes counting as subject (lenient, no false blocker) and drawnArt compositing onto black (only matters for art with alpha; provider art is opaque) are accepted as known limits, documented in spec §9 limits in fix round 2. — Lenient errors cost no money; the optional vision review covers aesthetics. — If wrong: a motif-less gradient passes deterministic QA.
- **R28:** providerUse gates EVERY asset type sent to any AI provider (style references in visual.ts, vision review in Task 10) through one shared helper `mayTransmitToProvider(assetData): boolean` (approved + usageApproved + providerUse === true) in apps/api/src/modules/marketing/brand/provider-use.ts; existing style references of other types now also need the flag (ORBIT_IMAGE_REFERENCES is off by default, so no production change). — Spec §5/§13 ("only assets marked for provider use are sent"). — If wrong: owners must set providerUse on style references before references work.
- **R29:** artPrompt's placement sentence derives from the drawn-art frame: the text zone = artZones(layout)[0] (text zone clipped to the art box). If no text zone intersects the art box (strip/sub-region art), the placement sentence asks for a centred, frame-filling subject with even margins instead of a calm text area. Applied in Task 8's fix round. — R21 consistency; a strip art must not reserve calm space for text that is not on it. — If wrong: placement wording on strip templates only.
