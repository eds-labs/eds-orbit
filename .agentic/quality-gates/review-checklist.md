# Review Checklist

## Korrektheit

- Löst der Code das eigentliche Problem?
- Gibt es Edge Cases?
- Gibt es Race Conditions?
- Sind Fehlerfälle explizit behandelt?

## Architektur

- Passt die Änderung zum bestehenden Design?
- Wurde unnötige Komplexität eingeführt?
- Sind Verantwortlichkeiten sauber getrennt?

## Tests

- Decken Tests den kritischen Pfad ab?
- Gibt es Negativfälle?
- Sind Tests stabil und wartbar?

## Wartbarkeit

- Sind Namen klar?
- Ist die Logik verständlich?
- Gibt es Duplikate?
- Sind Kommentare hilfreich und aktuell?

## Sicherheit

- Werden Eingaben validiert?
- Sind Berechtigungen korrekt?
- Werden Secrets geschützt?
