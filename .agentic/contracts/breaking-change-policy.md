# Breaking Change Policy

## Breaking Changes

- Feld entfernen
- Feldtyp ändern
- Required Field hinzufügen
- Status Code ändern
- Fehlerformat ändern
- Auth-Anforderung verschärfen oder lockern
- Semantik eines bestehenden Feldes ändern

## Vorgehen

1. Kompatible Erweiterung bevorzugen.
2. Deprecation markieren.
3. Clients identifizieren.
4. Migration/Kommunikation planen.
5. Versionierung prüfen.

## Codex-Regel

Bei potenziellen Breaking Changes muss Codex diese explizit nennen.
