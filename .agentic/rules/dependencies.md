# Dependency Rules

## Neue Dependencies

Neue Produktionsabhängigkeiten nur, wenn:

- sie ein echtes Problem lösen,
- sie aktiv gepflegt sind,
- sie sicherheitlich vertretbar sind,
- Bundle-/Runtime-Kosten akzeptabel sind,
- keine einfache vorhandene Lösung existiert.

## Vor Installation prüfen

- Gibt es bereits eine passende Dependency im Projekt?
- Ist die Dependency für Client oder Server gedacht?
- Hat sie bekannte Sicherheits-/Lizenzrisiken?
- Ist sie für den Umfang der Aufgabe überdimensioniert?

## Abschluss

- Dependency-Änderungen in Summary nennen.
- Lockfile-Änderungen prüfen.
- Build und Tests ausführen.
