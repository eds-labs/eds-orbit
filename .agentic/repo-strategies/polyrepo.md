# Repo Strategy: Polyrepo

## Geeignet für

- unabhängige Teams
- getrennte Release-Zyklen
- externe Services mit klaren Verträgen
- Enterprise Ownership

## Risiken

- Contract Drift
- doppelte Config
- komplexere lokale Entwicklung
- mehr CI/CD-Aufwand

## Pflicht

- klare API Contracts
- Versionierung
- gemeinsame Standards dokumentieren
